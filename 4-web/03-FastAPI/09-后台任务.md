# 09-后台任务

> Python 3.11+

本章讲解 FastAPI 后台任务处理。

---

## 概念铺垫

FastAPI 的 `BackgroundTasks` 基于 Starlette 的 `BackgroundTask` 类实现，核心原理是在**响应发送之后、连接关闭之前**执行任务。这意味着：

- 客户端在收到 HTTP 响应后，后台任务才开始执行
- 任务与请求共享同一个事件循环（同步任务会阻塞事件循环）
- 任务不可持久化：进程重启即丢失
- 任务不提供重试、监控、优先级等特性

```
请求到达 → 路由处理 → 添加 bg_task → 发送响应 → 执行 bg_task → 连接关闭
```

对于需要持久化、分布式、重试机制的任务，应使用专业任务队列（Celery、RQ、Dramatiq）。

**选型建议**：

```
任务是否需要在进程重启后仍然存在？
    ├── 是 ──> Celery / RQ（持久化到 Broker）
    │
    └── 否 ──> 任务执行时间是否 < 5 秒？
                 ├── 是 ──> BackgroundTasks
                 │
                 └── 否 ──> 是否需要重试/监控？
                              ├── 是 ──> Celery
                              │
                              └── 否 ──> asyncio.create_task()
```

## 第一部分：BackgroundTasks

### 1.1 实际场景

发送邮件、生成报表等耗时操作不应该阻塞 HTTP 响应，应该在后台执行。

**问题：如何在响应后执行后台任务？**

### 1.2 基本使用

```python
from fastapi import FastAPI, BackgroundTasks

app: FastAPI = FastAPI()


def write_log(message: str) -> None:
    with open("log.txt", "a") as f:
        f.write(f"{message}\n")


@app.post("/send-email/{email}")
async def send_email(email: str, background_tasks: BackgroundTasks) -> dict[str, str]:
    background_tasks.add_task(write_log, f"Email sent to {email}")
    return {"message": "Email is being sent"}
```

### 1.3 带参数的任务

```python
def process_data(data: str, count: int) -> None:
    for i in range(count):
        print(f"Processing {data}: {i+1}/{count}")


@app.post("/process")
async def process(
    data: str,
    count: int = 5,
    background_tasks: BackgroundTasks = None
) -> dict[str, str]:
    background_tasks.add_task(process_data, data, count)
    return {"message": "Processing started"}
```


### 2.3 Celery 配置

```python
# celery_config.py
from celery import Celery

celery_app: Celery = Celery(
    'tasks',
    broker='redis://localhost:6379/0',
    backend='redis://localhost:6379/1'
)


@celery_app.task
def send_email_task(to: str, subject: str, body: str) -> dict[str, str]:
    import time
    time.sleep(2)
    print(f"Email sent to {to}")
    return {"status": "sent", "to": to}


@celery_app.task
def process_data_task(data: list) -> dict[str, int]:
    result: int = sum(data)
    return {"result": result, "count": len(data)}
```

### 2.4 FastAPI 中使用

```python
from fastapi import FastAPI
from celery_config import celery_app, send_email_task, process_data_task

app: FastAPI = FastAPI()


@app.post("/send-email")
async def send_email(email: str, subject: str, body: str) -> dict[str, str]:
    task = send_email_task.delay(email, subject, body)
    return {"task_id": task.id, "status": "queued"}


@app.post("/process")
async def process_data(numbers: list) -> dict[str, str]:
    task = process_data_task.delay(numbers)
    return {"task_id": task.id, "status": "queued"}


@app.get("/task/{task_id}")
async def get_task_status(task_id: str) -> dict[str, str | None]:
    task = celery_app.AsyncResult(task_id)
    return {
        "task_id": task.id,
        "status": task.state,
        "result": task.result if task.ready() else None
    }
```

## 第三部分：完整示例

```python
from fastapi import FastAPI, BackgroundTasks
from pydantic import BaseModel
import time

app: FastAPI = FastAPI()


# ==================== 任务函数 ====================
def write_notification(email: str, message: str) -> None:
    """写入通知日志"""
    with open("notifications.txt", "a") as f:
        f.write(f"Email: {email}, Message: {message}\n")


def send_email_async(email: str, subject: str, body: str) -> None:
    """模拟发送邮件"""
    time.sleep(2)  # 模拟耗时操作
    print(f"Email sent: {subject} to {email}")


def process_batch(items: list[dict]) -> list[dict]:
    """批量处理"""
    results: list[dict] = []
    for item in items:
        time.sleep(0.5)
        results.append({"processed": item})
    return results


# ==================== 路由 ====================
class EmailRequest(BaseModel):
    email: str
    subject: str
    body: str


class ProcessRequest(BaseModel):
    items: list[dict]


@app.post("/notify")
async def notify(email: str, message: str, background_tasks: BackgroundTasks) -> dict[str, str]:
    background_tasks.add_task(write_notification, email, message)
    return {"message": "Notification queued"}


@app.post("/email")
async def send_email(request: EmailRequest, background_tasks: BackgroundTasks) -> dict[str, str]:
    background_tasks.add_task(
        send_email_async,
        request.email,
        request.subject,
        request.body
    )
    return {"message": "Email sending in background"}


@app.post("/batch")
async def process_batch_items(request: ProcessRequest, background_tasks: BackgroundTasks) -> dict[str, int]:
    task = background_tasks.add_task(
        process_batch,
        request.items
    )
    return {"message": "Batch processing started", "task_id": id(task)}
```

### L2 实践层：用好

## 最佳实践

### 1. 同步任务必须轻量

```python
# ✅ 同步任务：日志写入、内存缓存更新（毫秒级）
def write_log(message: str):
    with open("app.log", "a") as f:
        f.write(f"{datetime.now()}: {message}\n")

# ❌ 同步任务：CPU 密集、同步 I/O（会阻塞事件循环）
def generate_report(user_id: int):
    time.sleep(30)  # 阻塞事件循环 30 秒！
    ...
```

**规则**：BackgroundTasks 中的同步任务应该 < 1 秒。超过 1 秒的任务应：
- 使用 `async def` 异步任务（不阻塞事件循环）
- 或使用 Celery 等外部队列

### 2. 任务幂等性

```python
# ✅ 幂等任务（重复执行安全）
def update_cache(key: str, value: str):
    cache.set(key, value, ttl=300)  # 覆盖写入，幂等

# ❌ 非幂等任务（重复执行导致问题）
def send_sms(phone: str, message: str):
    sms_api.send(phone, message)  # 重复执行会重复发送短信
```

### 3. 任务状态追踪

```python
from pydantic import BaseModel
import asyncio

class TaskRecord(BaseModel):
    id: int
    status: str  # "pending" | "running" | "completed" | "failed"
    result: str | None = None

async def execute_with_tracking(task_id: int, coro: asyncio.Coroutine):
    await db.tasks.update(task_id, status="running")
    try:
        result = await coro
```

## 反模式

| ❌ 反模式 | ✅ 改进 |
|-----------|---------|
| BackgroundTasks 中执行同步耗时操作（如 `time.sleep(30)`） | 使用 async 任务或 Celery |
| 发送邮件、短信直接放 BackgroundTasks | 放入 Celery，获得重试和持久化 |
| BackgroundTasks 中修改响应数据 | BackgroundTasks 在响应发送后才执行 |
| 不处理任务异常，静默失败 | async 任务捕获异常并记录日志 |
| 在 BackgroundTasks 中执行数据库写入（无事务保护） | 使用 Celery 或先写入数据库再异步处理 |
| 错误的参数顺序 `add_task(args...)` | `add_task(func, arg1, arg2)` — 函数在前，参数在后 |

## 何时选用什么

| 场景 | 方案 | 原因 |
|------|------|------|
| 写日志 | BackgroundTasks（同步） | 毫秒级，进程内 |
| 发送确认邮件 | Celery | 需要重试、持久化 |
| 数据缓存更新 | BackgroundTasks | 幂等、秒级 |
| 报表生成 | Celery | 分钟级、需监控 |
| 异步 Webhook 通知 | asyncio.create_task() | 异步 I/O、非阻塞 |
| 定时任务 | Celery Beat 或 APScheduler | 需要调度 |
| 文件异步处理 | Celery Worker | 分布到其他进程 |

## 第四部分：L3 专家层

### 4.1 BackgroundTasks 的事件循环调度机制

FastAPI 的 `BackgroundTasks` 基于 Starlette 的 `BackgroundTask` 类实现，其核心原理是在 **响应发送之后、连接关闭之前** 调度任务执行。

**底层流程：**

```
HTTP Request
     │
     ▼
┌─────────────────────────┐
│   ASGI Application      │
│   (FastAPI / Starlette) │
│                         │
│  1. 路由匹配             │
│  2. 依赖注入             │
│  3. 执行 endpoint        │
│     └─> tasks.append()  │  ◄── background_tasks.add_task()
└────────────┬────────────┘
             │
             ▼
┌─────────────────────────┐
│   Response Streaming    │
│   发送 HTTP 响应体       │
└────────────┬────────────┘
             │
             ▼
┌─────────────────────────┐
│   BackgroundTask.call() │  ◄── 响应发送完毕后触发
│   ───────────────────── │
│   for task in tasks:    │
│       if isasync(task): │
│           await task()  │
│       else:             │
│           task()        │  ◄── 同步任务直接调用
└────────────┬────────────┘
             │
             ▼
      Connection Close
```

关键实现位于 Starlette 的 `Response` 类中，`background` 属性在 `__call__` 方法的最后被调用：

```python
# Starlette 源码逻辑示意（简化版）
class Response:
    def __init__(self, background: BackgroundTask | None = None) -> None:
        self.background = background

    async def __call__(self, scope, receive, send) -> None:
        await send({"type": "http.response.start", ...})
        await send({"type": "http.response.body", ...})
        if self.background:
            await self.background(scope, receive, send)  # ◄── 在这里执行
```

**事件循环中的位置：**

```
Event Loop Tick
─────────────────────────────────────────
  │
  ├── Callbacks (I/O 完成)
  │     └── 读取请求体、写入响应体
  │
  ├── Ready Tasks (可运行的协程)
  │     └── endpoint 执行
  │
  └── Background Tasks (响应后)
        └── BackgroundTask.call()  ◄── 本 tick 的最后一个阶段
```

同步任务会 **阻塞事件循环**，因此同步任务应该是轻量操作（如写日志）。重任务应使用 `async def` 或外部队列。

### 4.2 Celery vs FastAPI BackgroundTasks 对比

| 维度 | BackgroundTasks | Celery |
|------|----------------|--------|
| **执行位置** | 同一进程、同一事件循环 | 独立 Worker 进程（可分布式） |
| **持久化** | 无，进程重启即丢失 | Broker（Redis/RabbitMQ）持久化 |
| **任务重试** | 不支持 | 内置重试机制（`max_retries`） |
| **任务监控** | 无内置监控 | Flower / Admin 可视化监控 |
| **延迟执行** | 不支持 | `apply_async(countdown=...)` |
| **任务优先级** | 不支持 | 优先级队列 |
| **适用场景** | 写日志、发送通知（秒级） | 数据导入、报表生成（分钟~小时级） |
| **运维成本** | 零额外依赖 | 需要 Broker + Worker 部署 |

**选型决策树：**

```
任务是否需要在进程重启后仍然存在？
    ├── 是 ──> Celery
    │
    └── 否 ──> 任务执行时间是否 < 5 秒？
                 ├── 是 ──> BackgroundTasks
                 │
                 └── 否 ──> 是否需要重试/监控？
                              ├── 是 ──> Celery
                              │
                              └── 否 ──> asyncio.create_task()
```

### 4.3 任务的持久化与监控

对于生产环境，仅靠 BackgroundTasks 无法满足任务的可观测性需求。常见的持久化方案：

**方案一：数据库 + BackgroundTasks**

```python
from fastapi import FastAPI, BackgroundTasks
from pydantic import BaseModel
import asyncio

app: FastAPI = FastAPI()


class TaskRecord(BaseModel):
    id: int
    status: str  # "pending" | "running" | "completed" | "failed"
    result: str | None = None


async def execute_with_tracking(
    task_id: int,
    coro: asyncio.Coroutine,
) -> None:
    """带状态跟踪的任务执行器"""
    # 1. 更新状态为 running
    await update_task_status(task_id, "running")
    try:
        result = await coro
        # 2. 更新状态为 completed
        await update_task_status(task_id, "completed", result=str(result))
    except Exception as e:
        # 3. 更新状态为 failed
        await update_task_status(task_id, "failed", error=str(e))


async def update_task_status(
    task_id: int,
    status: str,
    result: str | None = None,
    error: str | None = None,
) -> None:
    """模拟更新数据库"""
    print(f"Task {task_id}: {status} | result={result} | error={error}")


@app.post("/tracked-task/{task_id}")
async def create_tracked_task(
    task_id: int,
    background_tasks: BackgroundTasks,
) -> dict[str, int | str]:
    background_tasks.add_task(
        execute_with_tracking,
        task_id,
        asyncio.sleep(2),  # 模拟异步任务
    )
    return {"task_id": task_id, "status": "pending"}


@app.get("/task/{task_id}")
async def get_task(task_id: int) -> dict[str, str | int]:
    return {"task_id": task_id, "status": "completed", "result": "done"}
```

**监控指标体系：**

```
┌──────────────────────────────────────────────┐
│              Task Monitoring                  │
├──────────────────────────────────────────────┤
│                                              │
│  ┌──────────┐   ┌──────────┐   ┌──────────┐ │
│  │ Queue    │   │ Execution│   │ Result   │ │
│  │ Length   │   │ Duration │   │ Status   │ │
│  └────┬─────┘   └────┬─────┘   └────┬─────┘ │
│       │              │              │        │
│       ▼              ▼              ▼        │
│  积压告警         超时告警        失败告警    │
│  (>1000)         (>5min)         (rate>5%)  │
│                                              │
└──────────────────────────────────────────────┘
```

## 常见坑点排查

### 坑点 1：BackgroundTasks 中的同步函数阻塞事件循环

**错误现象**：应用响应越来越慢，最终超时。SSH 到服务器后，CPU 空闲但请求排队。

**根因**：在 BackgroundTasks 中执行 `time.sleep(30)` 或同步 HTTP 请求，直接阻塞了 asyncio 事件循环，导致后续请求无法处理。

```python
# ❌ 崩溃等待发生
def send_heavy_email(to: str):
    time.sleep(10)  # 阻塞事件循环 10 秒
    email_api.send(to)

@app.post("/send")
def send(bg: BackgroundTasks, to: str):
    bg.add_task(send_heavy_email, to)
    return {"status": "ok"}
```

**修复**：

```python
import asyncio

# ✅ 异步任务
async def send_heavy_email_async(to: str):
    await asyncio.sleep(10)  # 不阻塞事件循环
    await email_api.async_send(to)

# ✅ 或使用线程池
def send_heavy_email(to: str):
    time.sleep(10)
    email_api.send(to)

@app.post("/send")
async def send(bg: BackgroundTasks, to: str):
    bg.add_task(asyncio.to_thread, send_heavy_email, to)  # 放到线程池
    return {"status": "ok"}
```

### 坑点 2：BackgroundTasks 访问响应数据

**错误现象**：

```python
@app.post("/items")
async def create(item: Item, bg: BackgroundTasks):
    result = process_item(item)
    bg.add_task(log_action, result.status)  # result 可能已被销毁
    return result
```

**根因**：BackgroundTasks 在响应发送后才执行。如果 `result` 对象在响应后被 GC 回收，任务中访问会失败。

**修复**：任务参数使用可序列化的简单类型：

```python
@app.post("/items")
async def create(item: Item, bg: BackgroundTasks):
    result = process_item(item)
    bg.add_task(log_action, item_id=result.id, status=result.status)
    return result
```

### 坑点 3：Celery beat 定时任务重复执行

**错误现象**：同一时间点任务被执行了两次（或多次）。

**根因**：多个 Celery worker 或 beat 实例同时运行，缺少分布式锁。

**修复**：使用 Redis 锁确保只有一个实例执行：

```python
import redis
from celery import Celery

celery_app = Celery("tasks", broker="redis://localhost:6379/0")
redis_client = redis.Redis()

@celery_app.task
def scheduled_task():
    lock = redis_client.lock("scheduled_task_lock", timeout=300)
    if lock.acquire(blocking=False):
        try:
            do_work()
        finally:
            lock.release()
    else:
        print("Task already running, skipped")
```

### 坑点 4：add_task 参数顺序错误

**错误现象**：

```python
bg.add_task("hello", write_log)  # TypeError: 'str' object is not callable
```

**根因**：`add_task(func, *args, **kwargs)` — 第一个参数是函数，不是函数参数。

**修复**：

```python
bg.add_task(write_log, "hello")  # ✅ func, *args
```

### 坑点排查表

| 现象 | 根因 | 修复 | 预防 |
|------|------|------|------|
| 所有请求变慢 | 同步函数阻塞事件循环 | 用 async 或 `asyncio.to_thread()` | Code review 检查任务函数 |
| 任务中访问响应数据报错 | 对象已被 GC | 传递简单类型参数 | 不用可变对象作为任务参数 |
| 定时任务重复执行 | 多实例竞争 | Redis 分布式锁 | 单 beat 实例或使用锁 |
| `add_task` TypeError | 参数顺序错误 | `add_task(func, *args)` | IDE 类型提示 |
| 进程重启后任务丢失 | BackgroundTasks 无持久化 | 改用 Celery/RQ | 评估任务重要性选型 |
| Celery 任务永远 PENDING | broker 连接失败 | 检查 Redis 连接配置 | 健康检查端点 |

## 进阶用法

### 5.1 Lifespan 事件（启动与关闭）

```python
from contextlib import asynccontextmanager
from fastapi import FastAPI
import asyncpg
import redis.asyncio as redis


class AppState:
    """应用全局状态管理"""
    def __init__(self):
        self.db_pool: asyncpg.Pool | None = None
        self.redis: redis.Redis | None = None
        self._ready = False

    @property
    def ready(self) -> bool:
        return self._ready

    async def initialize(self):
        self.db_pool = await asyncpg.create_pool(
            dsn="postgresql://user:pass@localhost:5432/mydb",
            min_size=5,
            max_size=20,
        )
        self.redis = await redis.from_url("redis://localhost:6379")
        self._ready = True
        return self

    async def cleanup(self):
        self._ready = False
        if self.db_pool:
            await self.db_pool.close()
        if self.redis:
            await self.redis.aclose()


state = AppState()


@asynccontextmanager
async def lifespan(app: FastAPI):
    """应用生命周期管理"""
    # STARTUP: 在服务接受请求前执行
    print("Starting up...")
    await state.initialize()
    print("Database pool created, Redis connected")

    # 启动后台维护任务
    cleanup_task = asyncio.create_task(periodic_cleanup())

    yield  # ← 应用运行中...

    # SHUTDOWN: 在服务停止前执行
    print("Shutting down...")
    cleanup_task.cancel()
    try:
        await cleanup_task
    except asyncio.CancelledError:
        pass
    await state.cleanup()
    print("All resources released")


app = FastAPI(lifespan=lifespan)


# 健康检查端点
@app.get("/health")
def health() -> dict:
    return {
        "status": "ok" if state.ready else "starting",
        "db": state.db_pool is not None,
        "redis": state.redis is not None,
    }
```

### 5.2 定期任务（APScheduler）

```python
from apscheduler.schedulers.asyncio import AsyncIOScheduler
from apscheduler.triggers.cron import CronTrigger
from apscheduler.triggers.interval import IntervalTrigger
import asyncio

scheduler = AsyncIOScheduler()


async def cleanup_expired_sessions():
    """每小时清理过期 session"""
    print("Cleaning expired sessions...")


async def generate_daily_report():
    """每日凌晨 2 点生成日报"""
    print(f"Generating daily report at {datetime.now()}")


async def sync_user_data():
    """每 5 分钟同步用户数据"""
    print("Syncing user data...")


def setup_scheduler():
```

### 5.3 完整任务状态追踪系统

```python
from datetime import datetime, timezone
from enum import Enum
from pydantic import BaseModel
import hashlib

class TaskStatus(str, Enum):
    PENDING = "pending"
    RUNNING = "running"
    COMPLETED = "completed"
    FAILED = "failed"
    RETRYING = "retrying"


class TaskRecord(BaseModel):
    task_id: str
    name: str
    status: TaskStatus = TaskStatus.PENDING
    params: dict | None = None
    result: dict | None = None
    error: str | None = None
    retries: int = 0
    max_retries: int = 3
    created_at: str = ""
    updated_at: str = ""
    started_at: str | None = None
    completed_at: str | None = None


class TaskTracker:
    """任务状态追踪器（内存版，生产环境应接入数据库/Redis）"""

    def __init__(self):
        self._tasks: dict[str, TaskRecord] = {}
        self._semaphore = asyncio.Semaphore(10)  # 最多 10 个并发任务

    def create_task(self, name: str, params: dict | None = None) -> TaskRecord:
        now = datetime.now(timezone.utc).isoformat()
        task_id = hashlib.md5(f"{name}{now}".encode()).hexdigest()[:12]
        record = TaskRecord(
            task_id=task_id,
            name=name,
            params=params,
            created_at=now,
            updated_at=now,
        )
        self._tasks[task_id] = record
        return record

    async def execute(self, name: str, coro_func, **params):
        """执行带追踪的任务"""
        record = self.create_task(name, params)
        record.status = TaskStatus.RUNNING
        record.started_at = datetime.now(timezone.utc).isoformat()
        record.updated_at = record.started_at

        async with self._semaphore:
            try:
                result = await coro_func(**params)
                record.status = TaskStatus.COMPLETED
                record.result = {"data": str(result)}
            except Exception as e:
                if record.retries < record.max_retries:
                    record.retries += 1
                    record.status = TaskStatus.RETRYING
                    record.error = str(e)
                else:
                    record.status = TaskStatus.FAILED
                    record.error = str(e)

            record.completed_at = datetime.now(timezone.utc).isoformat()
            record.updated_at = record.completed_at

        return record

    def get_task(self, task_id: str) -> TaskRecord | None:
        return self._tasks.get(task_id)

    def list_tasks(self, status: TaskStatus | None = None) -> list[TaskRecord]:
        tasks = list(self._tasks.values())
        if status:
            tasks = [t for t in tasks if t.status == status]
        return sorted(tasks, key=lambda t: t.created_at, reverse=True)

    @property
    def active_count(self) -> int:
        return sum(1 for t in self._tasks.values() if t.status == TaskStatus.RUNNING)


task_tracker = TaskTracker()


@app.post("/tasks/process")
async def create_task(background_tasks: BackgroundTasks, data: str):
    async def worker(data: str):
        await asyncio.sleep(2)  # 模拟工作
        return f"processed: {data}"

    record = await task_tracker.execute("process_data", worker, data=data)
    return {"task_id": record.task_id, "status": record.status}


@app.get("/tasks/{task_id}")
def get_task_status(task_id: str) -> dict:
    record = task_tracker.get_task(task_id)
    if not record:
        raise HTTPException(404, f"Task {task_id} not found")
    return record.model_dump()


@app.get("/tasks")
def list_tasks(status: TaskStatus | None = None) -> list[dict]:
    records = task_tracker.list_tasks(status)
    return [r.model_dump() for r in records]
```

### 5.4 带指数退避的重试机制

```python
import asyncio
import random
from functools import wraps
from typing import Callable, Awaitable, TypeVar

T = TypeVar("T")


def with_retry(
    max_retries: int = 3,
    base_delay: float = 1.0,
    max_delay: float = 60.0,
    backoff_factor: float = 2.0,
    retryable_exceptions: tuple = (Exception,),
) -> Callable:
    """指数退避重试装饰器"""

    def decorator(func: Callable[..., Awaitable[T]]) -> Callable[..., Awaitable[T]]:
        @wraps(func)
        async def wrapper(*args, **kwargs) -> T:
            last_exception = None
            for attempt in range(max_retries + 1):
                try:
                    return await func(*args, **kwargs)
                except retryable_exceptions as e:
                    last_exception = e
                    if attempt < max_retries:
                        delay = min(
                            base_delay * (backoff_factor ** attempt),
                            max_delay,
                        )
                        jitter = random.uniform(0, delay * 0.5)
                        total_delay = delay + jitter
                        logger.warning(
                            f"Retry {attempt + 1}/{max_retries} for {func.__name__} "
                            f"after {total_delay:.1f}s: {e}"
                        )
                        await asyncio.sleep(total_delay)
                    else:
                        logger.error(
                            f"All {max_retries} retries failed for {func.__name__}: {e}"
                        )
            raise last_exception
        return wrapper
    return decorator


# 使用示例
@with_retry(
    max_retries=5,
    base_delay=1.0,
    max_delay=30.0,
    retryable_exceptions=(httpx.HTTPError, asyncio.TimeoutError),
)
async def call_external_api(url: str) -> dict:
    async with httpx.AsyncClient(timeout=10) as client:
        resp = await client.get(url)
        resp.raise_for_status()
        return resp.json()
```

### 5.5 监控指标（Prometheus）

```python
from prometheus_client import Counter, Histogram, Gauge, generate_latest
from fastapi.responses import Response
import time

# 定义指标
tasks_total = Counter(
    "background_tasks_total",
    "Total number of background tasks",
    ["task_name", "status"],
)
tasks_duration = Histogram(
    "background_tasks_duration_seconds",
    "Background task duration in seconds",
    ["task_name"],
)
tasks_active = Gauge(
    "background_tasks_active",
    "Number of currently active background tasks",
)


async def monitored_task(name: str, coro_func, **params):
    """带 Prometheus 监控的任务执行"""
    tasks_active.inc()
    start = time.perf_counter()
    try:
        result = await coro_func(**params)
        tasks_total.labels(task_name=name, status="success").inc()
        return result
    except Exception as e:
        tasks_total.labels(task_name=name, status="failed").inc()
        raise
    finally:
        duration = time.perf_counter() - start
        tasks_duration.labels(task_name=name).observe(duration)
        tasks_active.dec()

def metrics():
    """Prometheus 指标端点"""
    return Response(content=generate_latest(), media_type="text/plain")
```

### 5.6 BackgroundTasks vs Celery vs ARQ 深度对比

```python
# ========== 方案一：BackgroundTasks（轻量） ==========
# 适用：写日志、发送简单通知、毫秒级任务
# 限制：无持久化、无重试、单进程、无优先级

# ========== 方案二：Celery（重量级） ==========
# 适用：邮件发送、报表生成、数据导入、分布式任务
# 能力：持久化（Redis/RabbitMQ）、重试、优先级、定时任务、监控

# ========== 方案三：ARQ（现代轻量） ==========
# 适用：Python 异步项目、需要持久化但不想引入 Celery 复杂度
# 能力：Redis 持久化、cron 任务、自动重试、Worker 监控

# ARQ 示例：
# from arq import create_pool
# from arq.connections import RedisSettings

# async def arq_startup(ctx):
#     ctx["db"] = await create_db_pool()

# async def send_email(ctx, to: str, subject: str) -> str:
#     await ctx["email_client"].send(to, subject)
#     return f"Sent to {to}"

# class WorkerSettings:
#     functions = [send_email]
#     on_startup = arq_startup
#     redis_settings = RedisSettings(host="localhost", port=6379)

# FastAPI 中调用:
```

| 维度 | BackgroundTasks | Celery | ARQ |
|------|----------------|--------|-----|
| 安装复杂度 | 零（内置） | 高（Broker + Worker） | 中（仅 Redis） |
| 持久化 | 无 | 有 | 有 |
| 重试机制 | 无 | 内置 | 内置 |
| 定时任务 | 需 APScheduler | Celery Beat | 内置 Cron |
| 并发控制 | 事件循环限制 | Worker 数量 | Worker 数量 |
| 监控面板 | 无 | Flower | arq-dashboard |
| 分布式 | 否 | 是 | 否（单 Redis） |
| Python 版本 | 3.8+ | 3.7+ | 3.8+ |
| async 原生支持 | 是 | 部分（5.0+） | 完全 |
