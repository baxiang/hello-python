# 05-认证授权

> Python 3.11+

本章讲解 FastAPI 用户认证和权限管理。

---

## 概念铺垫

FastAPI 的认证系统基于 OAuth2 规范和 JWT（JSON Web Token），通过依赖注入系统实现认证与授权的解耦。

```
登录流程：
  Client → POST /token (username+password) → Server
  Server → JWT access_token → Client
  Client → GET /users/me (Authorization: Bearer <token>) → Server
  Server → verify JWT → 返回用户信息
```

**核心组件：**
- **OAuth2PasswordBearer**：从 `Authorization` 请求头提取 Bearer token
- **JWT**：无状态 token，Header.Payload.Signature 三段式，支持 HS256（对称）和 RS256（非对称）
- **bcrypt**：密码哈希算法，内置 salt 和工作因子，故意设计为慢（防暴力破解）
- **依赖链**：`token → decode → get_current_user → endpoint`

**安全原则：**
- 永远不存储明文密码
- access_token 短期有效（15-30min），refresh_token 长期（7-30天）
- 密钥（SECRET_KEY）存储在环境变量中，不硬编码

**问题：如何实现登录和 Token 验证？**

### 3.2 登录接口

```python
from fastapi import HTTPException


@app.post("/token", response_model=Token)
async def login(form_data: OAuth2PasswordRequestForm = Depends()) -> Token:
    user: dict | None = authenticate_user(form_data.username, form_data.password)
    if not user:
        raise HTTPException(status_code=400, detail="Incorrect username or password")

    access_token: str = create_access_token(data={"sub": user["username"]})
    return Token(access_token=access_token, token_type="bearer")


def authenticate_user(username: str, password: str) -> dict | None:
    user: dict | None = get_user(username)
    if not user:
        return None
    if not verify_password(password, user["hashed_password"]):
        return None
    return user
```

### 3.3 受保护路由

```python
async def get_current_user(token: str = Depends(oauth2_scheme)) -> dict:

    if user is None:
```

## 反模式

| ❌ 反模式 | ✅ 改进 |
|-----------|---------|
| SECRET_KEY 硬编码在源码中 | 从环境变量或密钥管理服务读取 |
| access_token 有效期设为 7 天 | 设为 15-30 分钟，配合 refresh_token |
| 密码用 MD5/SHA256 哈希 | 使用 bcrypt 或 argon2（慢哈希 + 内置 salt） |
| Token 通过 URL 参数传递 | 通过 `Authorization: Bearer <token>` 请求头 |
| 不设置 `WWW-Authenticate` 响应头 | 401 响应添加该头，方便客户端自动处理 |
| 同一个依赖同时做认证+授权 | 拆分为 `get_current_user`（认证）+ `PermissionChecker`（授权） |
| 所有错误都返回 400 | 认证失败 401，权限不足 403，校验失败 422 |
| JWT payload 中放入大量数据 | 只放 user_id 和 role，其他信息从数据库查询 |

## 何时选用什么

| 需求 | 选用方案 |
|------|---------|
| 单体应用 + 简单认证 | HS256 + bcrypt + OAuth2PasswordBearer |
| 微服务 + 多服务验证 | RS256（公私钥）+ 各服务持有公钥验证 |
| SPA / 移动端 | OAuth2 授权码流程 + PKCE |
| 内部系统 / CLI 工具 | OAuth2 密码流程（`OAuth2PasswordBearer`） |
| 角色基础权限 | `RoleChecker`（RBAC） |
| 细粒度权限控制 | `PermissionChecker`（ABAC/权限字符串） |
| 需要 Token 吊销 | 短有效期 access_token + 黑名单，或 Redis 缓存 |

## 第六部分：L3 专家层

### 6.1 OAuth2 授权码流程 vs 密码流程

FastAPI 的 `OAuth2PasswordBearer` 实现的是 **OAuth2 密码流程（Resource Owner Password Credentials Grant）**，适用于前后端一体或可信客户端。现代 SPA/移动端应使用 **授权码流程（Authorization Code Grant + PKCE）**。

```
┌──────────┐  密码流程                    ┌──────────┐
│  Client  │──POST /token───────────────→│  Server  │
│          │  (username + password)       │          │
│          │←── access_token ────────────│          │
└──────────┘                            └──────────┘

┌──────────┐  授权码流程                  ┌──────────┐
│  Client  │──GET /authorize────────────→│  Server  │
│          │←── code ───────────────────│          │
│          │──POST /token───────────────→│          │
│          │  (code + PKCE verifier)      │          │
│          │←── access_token + refresh ──│          │
└──────────┘                            └──────────┘
```

| 对比维度 | 密码流程（Password Grant） | 授权码流程 + PKCE |
|----------|---------------------------|-------------------|
| 密码暴露 | 客户端直接持有用户密码 | 密码永不离开认证服务器 |
| 适用场景 | 内部系统、CLI 工具 | SPA、移动端、第三方应用 |
| Token 刷新 | 无 refresh_token | 支持 refresh_token 轮换 |
| 安全性 | 低（密码明文传输风险） | 高（PKCE 防中间人拦截） |
| FastAPI 内置 | `OAuth2PasswordBearer` | 需自行实现或用 `Authlib` |

### 6.2 JWT 签名算法对比：HS256 vs RS256

```
HS256（对称签名）                     RS256（非对称签名）
┌─────────────┐                       ┌─────────────┐
│ Secret Key  │                       │ Private Key │→ 签名
│  (共享密钥)  │→ 签名 + 验证          │ (服务方持有) │
│             │                       └─────────────┘
│ 性能：高     │                       ┌─────────────┐
│ 密钥管理：难 │                       │ Public Key  │→ 验证
│ 适用：单服务 │                       │ (公开分发)   │
└─────────────┘                       └─────────────┘
```

| 对比维度 | HS256 | RS256 |
|----------|-------|-------|
| 密钥类型 | 对称密钥（单一 secret） | 非对称密钥对（公私钥） |
| 签名速度 | 快（HMAC-SHA256） | 较慢（RSA 签名） |
| 验证速度 | 快 | 中等 |
| 密钥分发 | 所有验证方共享同一密钥 | 公钥可公开分发，私钥仅签发方持有 |
| 适用场景 | 单体应用、内部服务 | 微服务、第三方验证、SSO |
| `python-jose` 用法 | `algorithm="HS256"` | `algorithm="RS256"` |

```python
from typing import Tuple
import jwt  # PyJWT, 替代 python-jose

# RS256 示例
def generate_keypair() -> Tuple[str, str]:
    from cryptography.hazmat.primitives.asymmetric import rsa
    from cryptography.hazmat.primitives import serialization

    private_key = rsa.generate_private_key(
        public_exponent=65537,
        key_size=2048,
    )
    private_pem = private_key.private_bytes(
        encoding=serialization.Encoding.PEM,
        format=serialization.PrivateFormat.PKCS8,
        encryption_algorithm=serialization.NoEncryption(),
    ).decode()

    public_pem = private_key.public_key().public_bytes(
        encoding=serialization.Encoding.PEM,
        format=serialization.PublicFormat.SubjectPublicKeyInfo,
    ).decode()

    return private_pem, public_pem

def create_rs256_token(data: dict, private_key: str) -> str:
    return jwt.encode(data, private_key, algorithm="RS256")

def verify_rs256_token(token: str, public_key: str) -> dict:
    return jwt.decode(token, public_key, algorithms=["RS256"])
```

### 6.3 Bearer Token 传递机制

HTTP 规范（RFC 6750）规定 Bearer Token 通过 `Authorization` 请求头传递：

```
GET /users/me HTTP/1.1
Host: api.example.com
Authorization: Bearer <token>
Content-Type: application/json
```

```
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer realm="api"
```

| 传递方式 | 格式 | 安全性 |
|----------|------|--------|
| Authorization Header | `Authorization: Bearer <token>` | 推荐，HTTP 标准 |
| Query Parameter | `?access_token=<token>` | 不推荐（URL 会被日志/代理记录） |
| Request Body | `{"access_token": "<token>"}` | 仅限 POST，不通用 |

`OAuth2PasswordBearer` 源码核心逻辑：

```python
# fastapi/security/oauth2.py 简化版
class OAuth2PasswordBearer(OAuth2):
    async def __call__(self, request: Request) -> str:
        authorization: str | None = request.headers.get("Authorization")
        if not authorization:
            raise HTTPException(status_code=403, detail="Not authenticated")
        scheme, _, token = authorization.partition(" ")
        if scheme.lower() != "bearer":
            raise HTTPException(status_code=401, detail="Invalid authentication scheme")
        return token
```

### 6.4 性能考量

| 操作 | 耗时级别 | 说明 |
|------|----------|------|
| HS256 编码 | ~0.01ms | 纯内存 HMAC 运算 |
| RS256 编码 | ~0.5ms | RSA 签名计算 |
| bcrypt 哈希 | ~100-300ms | 故意设计为慢（防暴力破解） |
| JWT 解码 | ~0.001ms | 仅 Base64 + JSON 解析 |
| JWT 验证（HS256） | ~0.01ms | HMAC 校验 |
| JWT 验证（RS256） | ~0.1ms | RSA 公钥验证 |

### 6.5 设计动机

| 设计选择 | 动机 |
|----------|------|
| FastAPI 用 `Depends()` 注入认证 | 利用依赖注入系统实现认证逻辑的可复用和可测试 |
| OAuth2PasswordBearer 返回 token 字符串而非用户对象 | 解耦 token 解析与用户查询，用户由 `get_current_user` 负责 |
| JWT 无状态设计 | 避免服务端存储 session，水平扩展无需 session 同步 |
| bcrypt 而非 MD5/SHA | bcrypt 内置 salt 和 work factor，抗彩虹表和 GPU 暴力破解 |

### 6.6 知识关联

```
认证授权
├── OAuth2 协议 ──→ 密码流程（OAuth2PasswordBearer）
│                   └── 授权码流程 + PKCE（SPA/移动端）
│
├── JWT (JSON Web Token)
│   ├── 结构：Header.Payload.Signature
│   ├── HS256：对称签名（单体应用）
│   └── RS256：非对称签名（微服务/SSO）

│
├── 权限模型
```


### Level 2：带密码哈希 + 过期时间

```python
from passlib.context import CryptContext
from datetime import datetime, timedelta

pwd_context = CryptContext(schemes=["bcrypt"])

users = {
    "alice": {"username": "alice", "hashed": pwd_context.hash("pass123")}
}

def create_token(data: dict, expires_min: int = 30):
    data["exp"] = datetime.utcnow() + timedelta(minutes=expires_min)

@app.post("/token")
def token(username: str, password: str):
```

### Level 3：refresh token + 角色权限

```python
import secrets

refresh_tokens: dict[str, str] = {}

def create_refresh_token(username: str) -> str:
    rt = secrets.token_urlsafe(32)
    refresh_tokens[rt] = username
    return rt

@app.post("/token")
def login(form_data: OAuth2PasswordRequestForm = Depends()):
    user = authenticate(form_data.username, form_data.password)
    access = create_access_token({"sub": user["username"], "role": user["role"]})
    refresh = create_refresh_token(user["username"])
    return {"access_token": access, "refresh_token": refresh, "token_type": "bearer"}

@app.post("/refresh")
def refresh(refresh_token: str):
    username = refresh_tokens.get(refresh_token)
    if not username:
        raise HTTPException(401, "Invalid refresh token")
    # 吊销旧 token，生成新 token
    new_access = create_access_token({"sub": username})
    new_refresh = create_refresh_token(username)
    del refresh_tokens[refresh_token]
    return {"access_token": new_access, "refresh_token": new_refresh}

class RoleChecker:
    def __init__(self, roles: list[str]):
        self.roles = roles
    def __call__(self, user=Depends(get_current_user)):
        if user["role"] not in self.roles:
            raise HTTPException(403, "Insufficient role")
        return user

@app.get("/admin", dependencies=[Depends(RoleChecker(["admin"]))])
def admin_panel():
    return {"message": "Welcome admin"}
```

## 常见坑点排查

### 坑点 1：JWT 过期时间使用 utcnow 但服务器时区非 UTC

**症状：** Token 在预期时间之前/之后过期

```python
# ❌ datetime.utcnow() 返回 naive datetime（无时区信息）
expire = datetime.utcnow() + timedelta(minutes=30)

# ✅ 始终使用带时区的 UTC 时间
from datetime import datetime, timezone
expire = datetime.now(tz=timezone.utc) + timedelta(minutes=30)
```

### 坑点 2：`jwt.decode` 不验证签发者/受众

**症状：** 任何服务签发的 token 都能通过验证

```python
# ❌ 仅验证算法和签名
payload = jwt.decode(token, SECRET_KEY, algorithms=["HS256"])

# ✅ 额外验证 claims
payload = jwt.decode(
    token,
    SECRET_KEY,
    algorithms=["HS256"],
    options={
        "verify_exp": True,
        "verify_iss": True,    # 签发者
        "verify_aud": False,   # 受众（根据需求）
    },
    issuer="my-api-service",
)
```

### 坑点 3：将 bcrypt 用于每次请求的身份验证

**症状：** 每次请求耗时 ~200ms

```python
# ❌ 每次请求都重新验证密码（bcrypt 很慢）
async def get_current_user(token=Depends(oauth2_scheme)):
    user = await db.get_user(username)
    if not verify_password(cached_password, user.password):
        ...
```

**根因分析：** bcrypt 的设计目标是慢（100-300ms），防止暴力破解。但 JWT 已经承担了身份验证，不需要每次请求都验证密码。

```python
# ✅ JWT 验证即可（~0.01ms），不需要 bcrypt
async def get_current_user(token=Depends(oauth2_scheme)):
    payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
    user = await db.get_user(payload["sub"])
    return user
```

### 坑点 4：没有处理 token 类型（Bearer vs MAC）

**症状：** 任意格式的 Authorization header 都能通过

```python
# ❌ 不检查 scheme
def get_token(request: Request) -> str:
    return request.headers.get("Authorization", "").removeprefix("Bearer ").strip()

# ✅ 检查 scheme
def get_token(request: Request) -> str:
    auth = request.headers.get("Authorization", "")
    if not auth.lower().startswith("bearer "):
        raise HTTPException(401, "Invalid authorization scheme")
    return auth[7:].strip()
```

### 坑点排查速查表

| 症状 | 可能原因 | 解决方案 |
|------|---------|---------|
| Token 总是过期 | 服务器时钟不同步 | 使用 NTP 同步时间，或适当放宽 exp 窗口 |
| "Invalid token" 但 token 看上去正确 | SECRET_KEY 不匹配 | 检查所有服务使用相同的密钥 |
| 登出后 token 仍有效 | 未实现 token 吊销 | 使用短有效期 + Redis 黑名单 |
| 并发请求中 token 失效 | access_token 过期 | 实现 refresh token 流程 |
| 密码验证太慢 | bcrypt work factor 过高 | 默认 12 已足够，不要设 >14 |
| 无状态服务无法验证 token | 使用 HS256 | 切换为 RS256（各服务持有公钥） |

```python
import base64
import json

def inspect_jwt(token: str):
    """手动检查 JWT 内容（不验证签名）"""
    parts = token.split(".")
    if len(parts) != 3:
        print("ERROR: Not a valid JWT (expected 3 parts)")
        return

    header = json.loads(base64.urlsafe_b64decode(parts[0] + "=="))
    payload = json.loads(base64.urlsafe_b64decode(parts[1] + "=="))

    print("=== HEADER ===")
    for k, v in header.items():
        print(f"  {k}: {v}")

    print("\n=== PAYLOAD ===")
    for k, v in payload.items():
        if k == "exp":
            exp_time = datetime.fromtimestamp(v, tz=timezone.utc)
            remaining = exp_time - datetime.now(tz=timezone.utc)
            print(f"  {k}: {v} ({exp_time.isoformat()}, {remaining.total_seconds():.0f}s remaining)")
        elif k == "iat":
            iat_time = datetime.fromtimestamp(v, tz=timezone.utc)
            print(f"  {k}: {v} ({iat_time.isoformat()})")
        else:
            print(f"  {k}: {v}")
```

### Session vs Stateless 认证决策

| 维度 | Session (Stateful) | JWT (Stateless) |
|------|-------------------|-----------------|
| 存储 | 服务端存储 session 数据 | Token 自包含用户信息 |
| 水平扩展 | 需要 session 共享（Redis/DB） | 无需共享，任意实例验证 |
| 吊销 | 删除 session 即可 | 需要黑名单或短过期 |
| 性能 | session 查询（可能 Redis） | 本地 JWT 解析 (~0.01ms) |
| 安全 | 服务端完全控制 | token 泄露后无法服务端吊销 |
| Payload 大小 | 无限制 | 通常 < 4KB（HTTP Header 限制） |
| 适用 | 传统 Web 应用 | API / 微服务 / SPA |

### 多因素认证（MFA）流程

```python
import pyotp

@app.post("/auth/begin")
async def begin_auth(username: str, password: str):
    user = await authenticate(username, password)
    if not user:
        raise HTTPException(401, "Invalid credentials")

    if user.mfa_enabled:
        # 生成临时 token（短期有效，仅用于 MFA 验证）
        mfa_token = jwt.encode(
            {"sub": username, "mfa_pending": True},
            SECRET_KEY,
            algorithm=ALGORITHM,
            # 有效期 5 分钟
            expires_delta=timedelta(minutes=5),
        )
        return {"mfa_required": True, "mfa_token": mfa_token}
    else:
        return {"access_token": create_access_token({"sub": username})}


@app.post("/auth/mfa")
async def verify_mfa(mfa_token: str, code: str):
    payload = jwt.decode(mfa_token, SECRET_KEY, algorithms=[ALGORITHM])
    if not payload.get("mfa_pending"):
        raise HTTPException(401, "Invalid MFA token")

    user = await get_user(payload["sub"])
    totp = pyotp.TOTP(user.mfa_secret)

    if not totp.verify(code):
        raise HTTPException(401, "Invalid MFA code")

    access = create_access_token({"sub": user["username"]})
    return {"access_token": access, "token_type": "bearer"}
```

### Token 吊销模式对比

| 吊销方式 | 实现 | 优点 | 缺点 |
|---------|------|------|------|
| 短有效期 | access_token 15min | 无需存储，最简单 | 无法立即吊销 |
| 黑名单 | Redis/DB 存储吊销 token | 即时吊销 | 需存储，每次请求需查询 |
| 版本号 | user.jwt_version += 1 | 一次写入吊销所有 | 无法精确控制单个 token |
| Refresh Token 轮换 | 每次刷新换新 token 对 | 兼顾安全与性能 | 需维护 token 族 |

```python
# 基于 Redis 的高性能黑名单实现
import redis.asyncio as redis

async def revoke_token(token: str, ttl: int) -> None:
    """将 token JTI 加入黑名单，TTL = token 剩余有效期"""
    payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
    jti = payload.get("jti")
    if jti:
        # 使用 SETBIT 实现更高效的黑名单 (位图)
        await redis.set(f"token_bl:{jti}", "1", ex=ttl)

async def is_revoked(jti: str) -> bool:
    return await redis.exists(f"token_bl:{jti}") > 0
```

### Token 签发时注入 scopes

```python
def create_access_token(data: dict, scopes: list[str] | None = None) -> str:
    to_encode = data.copy()
    to_encode.update({
        "exp": datetime.now(tz=timezone.utc) + timedelta(minutes=30),
        "iat": datetime.now(tz=timezone.utc),
        "jti": str(uuid.uuid4()),  # 唯一 token ID，用于吊销
        "iss": "my-api-service",
        "scopes": scopes or [],
    })
    return jwt.encode(to_encode, SECRET_KEY, algorithm=ALGORITHM)

@app.post("/token")
async def login(form_data: OAuth2PasswordRequestForm = Depends()):
    user = await authenticate(form_data.username, form_data.password)
    if not user:
        raise HTTPException(401, "Invalid credentials")

    scopes = form_data.scopes or []
    # 验证用户是否有请求的 scopes
    user_allowed = set(user.get("scopes", []))
    if not set(scopes).issubset(user_allowed):
        raise HTTPException(403, "Insufficient scope")
    if not scopes:
        scopes = user.get("default_scopes", ["me:read"])

    return {
        "access_token": create_access_token({"sub": user["username"]}, scopes),
        "token_type": "bearer",
        "scope": " ".join(scopes),
    }
```

### JWT 安全性检查清单

| 检查项 | 要求 |
|-------|------|
| 算法白名单 | 只接受 `["HS256"]` 或 `["RS256"]`，拒绝 `"none"` 算法 |
| 过期验证 | `verify_exp=True` |
| 签发者验证 | `verify_iss=True` + 指定 `issuer` |
| 受众验证 | 需要时 `verify_aud=True` |
| 密钥安全 | 环境变量，不硬编码；RS256 私钥不提交 |
| 最小 Payload | 只放 user_id/role/exp 等核心字段 |
| HTTPS | 生产环境强制 HTTPS |
| Token 大小 | 控制在 HTTP Header 4KB 限制内 |
