# 06-中间件

> Python 3.11+

本章讲解 FastAPI 中间件和跨域处理。

---

## 概念铺垫

FastAPI 中间件基于 ASGI 规范，采用**洋葱模型（Onion Model）**：请求从外向内逐层穿过中间件，响应从内向外逐层返回。

```
          请求方向：外层 → 内层
          ┌──────────────────────────────┐
          │  CORSMiddleware (最外层)       │
          │  ┌──────────────────────────┐ │
          │  │  GZipMiddleware          │ │
          │  │  ┌──────────────────────┐ │ │
          │  │  │  自定义 Timing 中间件  │ │ │
          │  │  │  ┌────────────────┐  │ │ │
  请求 →  │→│→│→│→│   Router/App    │→┼←│←│←│ 响应
          │  │  │  └────────────────┘  │ │ │
          │  │  │  自定义 Timing 中间件  │ │ │
          │  │  └──────────────────────┘ │ │
          │  │  GZipMiddleware          │ │
          │  └──────────────────────────┘ │
          │  CORSMiddleware (最外层)       │
          └──────────────────────────────┘
          响应方向：内层 → 外层
```

**核心概念：**
- **注册顺序与执行顺序相反**：先注册的中间件在最外层（最后处理请求，最先处理响应）
- **CORS 预检**：CORSMiddleware 拦截 `OPTIONS` 请求，直接返回 CORS headers，不经过后续中间件和路由
- **BaseHTTPMiddleware**：简化了 ASGI 原生接口（`scope`/`receive`/`send`），提供 `request`/`response` 高级对象

中间件的典型用途：跨域处理、请求日志、性能监控、安全 Headers、认证前置检查。

## 第二部分：自定义中间件

### 2.1 实际场景

需要在每个请求中添加处理时间响应头，记录请求日志。

**问题：如何创建自定义中间件？**

### 2.2 基础中间件

```python
from fastapi import FastAPI, Request
import time

app: FastAPI = FastAPI()


@app.middleware("http")
async def add_process_time(request: Request, call_next):
    start_time: float = time.time()
    response = await call_next(request)
    process_time: float = time.time() - start_time
    response.headers["X-Process-Time"] = str(process_time)
    return response
```

### 2.3 请求日志中间件

```python
@app.middleware("http")
async def log_requests(request: Request, call_next):
    print(f"Request: {request.method} {request.url}")
    response = await call_next(request)
    print(f"Response: {response.status_code}")
    return response
```

## 第三部分：中间件进阶

### 3.1 实际场景

所有 API 请求需要验证 Token，除了登录和文档页面。

**问题：如何在中间件中实现认证逻辑？**

### 3.2 认证中间件

```python
from fastapi import FastAPI, Request, HTTPException
from starlette.middleware.base import BaseHTTPMiddleware

class AuthMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        # 公开路径
        public_paths: list[str] = ["/docs", "/openapi.json", "/token"]

        if request.url.path in public_paths:
            return await call_next(request)

        # 检查认证
        auth_header: str | None = request.headers.get("Authorization")
        if not auth_header or not auth_header.startswith("Bearer "):
            raise HTTPException(status_code=401, detail="Not authenticated")

        return await call_next(request)

app.add_middleware(AuthMiddleware)
```

```python
async def security_headers(request: Request, call_next):

@app.get("/")
async def root() -> dict[str, str]:
    return {"message": "Hello"}


@app.get("/slow")
async def slow() -> dict[str, str]:
```

### L2 实践层：用好

## 最佳实践

### 1. 中间件注册顺序

```
正确的注册顺序（从外到内）：

1. CORSMiddleware     ← 最先注册（最外层），拦截 OPTIONS 预检
2. 安全 Headers       ← X-Frame-Options, X-Content-Type-Options 等
3. 认证/Auth            ← JWT 验证（可选，建议用 Depends）
4. 日志/Timing         ← 记录请求方法、耗时、状态码
5. GZipMiddleware      ← 最后注册（最内层），在响应生成后压缩
6. App (最内层)        ← 路由处理
```

**关键原因**：
- CORS 必须在最外层：预检请求（OPTIONS）不应经过后续中间件
- GZip 应在最内层：在响应完整生成后再压缩，避免压缩未完成的响应
- `@app.middleware("http")` 装饰的中间件注册最晚（最内层）

### 2. 安全 Headers 标准配置

```python
@app.middleware("http")
async def security_headers(request: Request, call_next):
    response = await call_next(request)
    response.headers["X-Content-Type-Options"] = "nosniff"
    response.headers["X-Frame-Options"] = "DENY"
    response.headers["Strict-Transport-Security"] = "max-age=31536000; includeSubDomains"
    response.headers["Content-Security-Policy"] = "default-src 'self'"
    return response
```

### 3. CORS 配置规范

```python
# 开发环境
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],          # 允许所有来源
    allow_methods=["*"],
    allow_headers=["*"],
)

# 生产环境（严格限制）
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://app.example.com"],  # 白名单
    allow_credentials=True,
    allow_methods=["GET", "POST", "PUT", "DELETE"],
    allow_headers=["Authorization", "Content-Type"],
    max_age=600,  # 预检结果缓存 10 分钟
)
```

## 反模式

| ❌ 反模式 | ✅ 改进 |
|-----------|---------|
| 生产环境 `allow_origins=["*"]` | 指定具体白名单域名 |
| 中间件中执行同步阻塞操作（`time.sleep(5)`） | 异步操作或移至 BackgroundTasks |
| CORS 不用最外层注册 | CORS 必须 `add_middleware` 在最前面 |
| 在中间件中访问响应体内容 | 响应体可能是流式，应只操作 headers |
| 所有逻辑都放在中间件 | 认证用 `Depends`，中间件只处理横切关注点 |
| `@app.middleware` 装饰器与 `add_middleware` 混用无顺序意识 | 先注册 `add_middleware`（外层），再用装饰器（内层） |
| 中间件中直接修改 `scope` | 通过 `request.state` 或 `request.scope` 安全修改 |

## 何时选用什么

| 需求 | 选用方案 |
|------|---------|
| 跨域处理 | `CORSMiddleware` |
| 响应压缩 | `GZipMiddleware` |
| 请求日志/耗时 | `@app.middleware("http")` |
| 安全 Headers | `@app.middleware("http")` |
| Host 白名单 | `TrustedHostMiddleware` |
| 全局认证前置 | `BaseHTTPMiddleware` 子类 |
| 路由级认证 | `Depends(get_current_user)`（不推荐中间件） |
| 请求/响应内容修改 | `BaseHTTPMiddleware` |

## 第五部分：L3 专家层

### 5.1 ASGI 中间件的洋葱模型（Stacking Middleware）

FastAPI 中间件基于 ASGI 规范，采用**洋葱模型**：请求从外向内逐层穿过中间件，响应从内向外逐层返回。

```
         ┌──────────────────────────────────────┐
         │        Middleware A (CORS)           │
         │  ┌────────────────────────────────┐  │
         │  │    Middleware B (GZip)         │  │
         │  │  ┌──────────────────────────┐  │  │
         │  │  │   Middleware C (Timing)  │  │  │
         │  │  │  ┌────────────────────┐  │  │  │
    请求 →│→│→│→│→→│     Router/App     │→→│←│←│←│ 响应
         │  │  │  └────────────────────┘  │  │  │
         │  │  │   Middleware C (Timing)  │  │  │
         │  │  └──────────────────────────┘  │  │
         │  │    Middleware B (GZip)         │  │
         │  └────────────────────────────────┘  │
         │        Middleware A (CORS)           │
         └──────────────────────────────────────┘

    请求方向：外层 → 内层 (A → B → C → App)
    响应方向：内层 → 外层 (App → C → B → A)
```

```python
# 洋葱模型本质：每个中间件都是 awaitable 的嵌套调用
# 伪代码表示
async def middleware_a(scope, receive, send):
    # 请求前处理（外层）
    async def wrapped_send(message):
        # 响应后处理（外层）
        await send(message)
    await middleware_b(scope, receive, wrapped_send)

async def middleware_b(scope, receive, send):
    async def wrapped_send(message):
        await send(message)
    await middleware_c(scope, receive, wrapped_send)
```

### 5.2 Starlette 中间件的执行顺序

FastAPI 继承自 Starlette，中间件的执行顺序与**注册顺序相反**（后注册的更靠近 App，先处理请求）：

```python
app.add_middleware(A)  # 最外层（最后处理请求）
app.add_middleware(B)  # 中间层
app.add_middleware(C)  # 最内层（最先处理请求，最先接触响应）

# 请求流：Client → C → B → A → App → A → B → C → Client
#                          ↑ 最先到达       ↑ 最后离开
```

| 中间件 | 注册顺序 | 请求阶段位置 | 响应阶段位置 |
|--------|----------|-------------|-------------|
| CORSMiddleware | 第一个 | 最外层（最后执行） | 最外层（最后修改） |
| GZipMiddleware | 第二个 | 中间层 | 中间层 |
| 自定义中间件 | 最后一个 | 最内层（最先执行） | 最内层（最先修改） |

**关键规则**：
- CORS 必须最先注册（最外层），确保 OPTIONS 预检请求被优先处理
- GZip 应靠近 App（内层），在响应生成后再压缩
- 认证/日志中间件应放在 CORS 之后

`@app.middleware("http")` 内部通过 `Middleware` 包装为 `BaseHTTPMiddleware`：

```python
# fastapi/applications.py 简化版
def middleware(self, type: str = "http"):
    def decorator(func):
        self.add_middleware(Middleware, base_http_middleware_class=..., dispatch=func)
        return func
    return decorator
```

### 5.3 CORS 预检请求（Preflight）处理

浏览器对**非简单请求**（方法非 GET/POST/HEAD，或包含自定义 Header）会先发送 `OPTIONS` 预检请求：

```
Client                              Server
  │── OPTIONS /api/users ──────────→│
  │   Origin: http://localhost:3000 │
  │   Access-Control-Request-Method: DELETE
  │   Access-Control-Request-Headers: Authorization
  │                                 │
  │←─ 200 OK ──────────────────────│
  │   Access-Control-Allow-Origin: http://localhost:3000
  │   Access-Control-Allow-Methods: DELETE
  │   Access-Control-Allow-Headers: Authorization
  │   Access-Control-Max-Age: 600
  │                                 │
  │── DELETE /api/users ───────────→│  ← 实际请求
  │   Authorization: Bearer <token> │
  │←─ 204 No Content ──────────────│
```

```python
from fastapi import FastAPI, Request
from fastapi.middleware.cors import CORSMiddleware
from starlette.responses import PlainTextResponse

app: FastAPI = FastAPI()

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:3000"],
    allow_credentials=True,
    allow_methods=["GET", "POST", "PUT", "DELETE", "OPTIONS"],
    allow_headers=["Authorization", "Content-Type"],
    max_age=600,  # 预检结果缓存 600 秒
)

# CORSMiddleware 内部处理 OPTIONS 的逻辑（简化）
# class CORSMiddleware:
#     async def __call__(self, scope, receive, send):
#         if method == "OPTIONS" and "origin" in headers:
#             # 直接返回 CORS headers，不经过后续中间件和路由
#             response = PlainTextResponse("", headers=cors_headers)
#             await response(scope, receive, send)
#             return
```

| 触发预检的条件 | 不触发预检的条件 |
|---------------|-----------------|
| 自定义 Header（如 `Authorization`） | `Accept`, `Accept-Language`, `Content-Language` |
| `Content-Type: application/json` | `Content-Type: application/x-www-form-urlencoded` |
| 方法为 `PUT`、`DELETE`、`PATCH` | 方法为 `GET`、`HEAD`、`POST` |
| 携带凭证的跨域请求 | 同源请求 |

### 5.4 性能考量

| 操作 | 耗时级别 | 说明 |
|------|----------|------|
| CORS 预检检查 | ~0.001ms | 纯字符串比对 |
| 洋葱模型层间传递 | ~0.01ms/层 | 每次 `call_next` 增加一层 await |
| GZip 压缩（1MB） | ~5-10ms | CPU 密集型，`minimum_size` 应设合理值 |
| 中间件数量（10 层） | ~0.1ms 总开销 | 通常可忽略，但层数多时需关注 |

### 5.5 设计动机

| 设计选择 | 动机 |
|----------|------|
| `add_middleware` 反向注册顺序 | 后注册的中间件更接近 App，符合"先注册先处理全局事务"的直觉 |
| `BaseHTTPMiddleware` 封装 | 简化 ASGI 原生接口，提供 `request`/`response` 高级对象 |
| `@app.middleware("http")` 装饰器 | 零配置快速添加中间件，内部自动包装为 `BaseHTTPMiddleware` |
| CORS 拦截 OPTIONS | 预检请求不需要经过业务路由，提前返回减少不必要的处理开销 |

### 5.6 知识关联

```
中间件
├── ASGI 规范
│   ├── scope: dict（请求信息）
│   ├── receive: Awaitable（接收消息）
│   └── send: Callable（发送响应）
│
├── 洋葱模型（Stacking）
│   ├── 请求：外层 → 内层 → App
│   └── 响应：App → 内层 → 外层
│
├── Starlette 中间件类型
│   ├── CORSMiddleware：跨域资源共享
│   ├── GZipMiddleware：响应压缩
│   ├── TrustedHostMiddleware：Host 验证
│   └── BaseHTTPMiddleware：自定义基类
│
├── CORS 预检（Preflight）
│   ├── 触发条件：非简单方法、自定义 Header、JSON Content-Type
│   ├── 缓存：max_age 控制 OPTIONS 结果缓存时间
│   └── 凭证：allow_credentials 控制 Cookie/Authorization 传递
│
└── 中间件注册顺序
    ├── 最先注册：最外层（CORS 优先）
    ├── 最后注册：最内层（靠近 App）
    └── @app.middleware：最内层（最后注册）
```

### Level 3：Request ID 注入 + 结构化日志

```python
import uuid
import structlog
from fastapi import FastAPI, Request

logger = structlog.get_logger()
app = FastAPI()

@app.middleware("http")
async def request_id_middleware(request: Request, call_next):
    request_id = request.headers.get("X-Request-ID", str(uuid.uuid4()))
    structlog.contextvars.bind_contextvars(request_id=request_id)

    response = await call_next(request)
    response.headers["X-Request-ID"] = request_id
    request.state.request_id = request_id

    logger.info(
        "request",
        method=request.method,
        path=request.url.path,
        status=response.status_code,
    )
    structlog.contextvars.clear_contextvars()
    return response
```

### Level 4：生产级中间件栈（错误追踪 + 限流 + IP 白名单）

```python
import time
import uuid
from fastapi import FastAPI, Request, Response
from fastapi.responses import JSONResponse
from starlette.middleware.base import BaseHTTPMiddleware
import sentry_sdk


class ErrorTrackingMiddleware(BaseHTTPMiddleware):
    """集中错误追踪中间件 — 捕获未处理异常并上报 Sentry"""

    async def dispatch(self, request: Request, call_next):
        try:
            return await call_next(request)
        except Exception as exc:
            request_id = getattr(request.state, "request_id", "unknown")
            sentry_sdk.capture_exception(exc, extra={
                "request_id": request_id,
                "method": request.method,
                "path": request.url.path,
                "client": request.client.host if request.client else None,
            })
            return JSONResponse(
                status_code=500,
                content={"detail": "Internal server error", "request_id": request_id},
            )


class IPWhitelistMiddleware(BaseHTTPMiddleware):
    """IP 白名单中间件 — 仅允许指定 IP 范围访问"""

    def __init__(self, app, allowed_ips: list[str]):
        super().__init__(app)
        self.allowed_ips = set(allowed_ips)

    async def dispatch(self, request: Request, call_next):
        client_ip = request.client.host if request.client else None
        if client_ip and client_ip not in self.allowed_ips:
            return JSONResponse(status_code=403, content={"detail": "IP not allowed"})
        return await call_next(request)


class RateLimitMiddleware(BaseHTTPMiddleware):
    """滑动窗口限流中间件"""

    def __init__(self, app, max_requests: int = 60, window: int = 60):
        super().__init__(app)
        self.max_requests = max_requests
        self.window = window
        self._clients: dict[str, list[float]] = {}

    async def dispatch(self, request: Request, call_next):
        client_ip = request.client.host if request.client else "unknown"
        now = time.time()

        # 滑动窗口清理
        timestamps = self._clients.get(client_ip, [])
        timestamps = [t for t in timestamps if now - t < self.window]

        if len(timestamps) >= self.max_requests:
            retry_after = int(self.window - (now - timestamps[0]))
            return JSONResponse(
                status_code=429,
                content={"detail": "Too many requests", "retry_after": retry_after},
                headers={"Retry-After": str(retry_after)},
            )

        timestamps.append(now)
        self._clients[client_ip] = timestamps

        return await call_next(request)


# 组装完整中间件栈
app = FastAPI()

app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://app.example.com"],
    allow_credentials=True,
    allow_methods=["GET", "POST", "PUT", "DELETE"],
    allow_headers=["Authorization", "Content-Type"],
```

## 常见坑点排查

### 坑点 1：中间件中消费了请求体

**症状：** 端点中 `await request.body()` 返回空，`await request.json()` 报错

```python
# ❌ 中间件中读取了 request.body()
@app.middleware("http")
async def bad_middleware(request: Request, call_next):
    body = await request.body()  # 消费了流
    print(f"Body: {body}")
    return await call_next(request)  # 端点中 body 为空！
```

**根因分析：** ASGI 的 `receive()` 是单向流，一次读取后数据就没了。中间件中 `await request.body()` 消费了流，后续端点无法再获取。

```python
# ✅ 在中间件中缓存 body 并重建 receive
@app.middleware("http")
async def safe_body_middleware(request: Request, call_next):
    body = await request.body()
    print(f"Body preview: {body[:200]}")

    async def receive():
        return {"type": "http.request", "body": body}

    request._receive = receive
    return await call_next(request)
```

### 坑点 2：`@app.middleware` 装饰器中间件放在 CORS 之前

**症状：** OPTIONS 预检请求经历不必要的逻辑处理

```python
# ❌ 装饰器中间件在 CORS 内层，OPTIONS 也要走
@app.middleware("http")
async def auth_middleware(request, call_next):
    # CORS 预检请求也会到这里！
    if request.url.path != "/docs":
        check_auth(request)
    return await call_next(request)

app.add_middleware(CORSMiddleware, ...)  # CORS 在内层！顺序反了
```

```python
# ✅ CORS 先用 add_middleware 注册（最外层）
app.add_middleware(CORSMiddleware, ...)

@app.middleware("http")  # 装饰器在最内层
async def auth_middleware(request, call_next):
    # 预检请求已经被 CORS 拦截，不会到达这里
    ...
```

### 坑点 3：响应体 Streaming 时修改 Content-Length

**症状：** 客户端收到的数据被截断或挂起

```python
# ❌ 在流式响应中设置 Content-Length
@app.middleware("http")
async def bad_compression(request: Request, call_next):
    response = await call_next(request)
    # 流式响应的 Content-Length 未知，不应修改
    response.headers["Content-Length"] = "..."  # 可能导致数据截断
    return response
```

```python
# ✅ 对于流式响应，GZipMiddleware 知道如何正确压缩流式数据
app.add_middleware(
    GZipMiddleware,
    minimum_size=500,  # 小于 500 字节不压缩
)
```

### 坑点 4：在 CORS 中间件之后添加其他中间件导致响应 Headers 丢失

**症状：** 某些请求缺少 CORS headers

```python
# ❌ 自定义中间件中返回了早期响应，跳过了 CORS 中间件的响应处理
class BadMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        if some_condition:
            # 直接返回响应，跳过了外层 CORS 的响应处理路径
            return JSONResponse(status_code=403, content={"error": "nope"})
        return await call_next(request)
```

```python
# ✅ 在 BaseHTTPMiddleware 中返回响应时手动添加 CORS headers
from starlette.middleware.cors import CORSMiddleware

class FixedMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        if some_condition:
            response = JSONResponse(status_code=403, content={"error": "nope"})
            # 模拟 CORS headers（或提取 CORS 中间件添加 headers 的逻辑）
            response.headers["Access-Control-Allow-Origin"] = request.headers.get("origin", "*")
            return response
        return await call_next(request)
```

### 坑点排查速查表

| 症状 | 可能原因 | 排查方法 |
|------|---------|---------|
| Request body 为空 | 中间件消费了 body 流 | 检查中间件是否读了 `.body()` 没重建 receive |
| OPTIONS 返回 401 | 认证中间件在内层 | CORS 中间件必须在最外层 |
| CORS headers 缺失 | 中间件返回了早期响应 | 确保早期响应包含 CORS headers |
| 响应被截断 | 流式响应被错误处理 | 不对流式响应设置 Content-Length |
| 中间件不生效 | 注册顺序错误 | 打印 `[mw.__class__.__name__ for mw in app.user_middleware]` |
| 性能下降 | 中间件中有 I/O 阻塞 | 检查中间件中的同步调用 |

```python
    def __init__(self, app, inner_middleware, skip_paths: set[str]):
```

### IP 白名单/黑名单

```python
class IPAccessControl(BaseHTTPMiddleware):
    def __init__(self, app, whitelist: set[str] | None = None, blacklist: set[str] | None = None):
        super().__init__(app)
        self.whitelist = whitelist or set()
        self.blacklist = blacklist or set()

    async def dispatch(self, request: Request, call_next):
        client_ip = request.client.host if request.client else None
        if not client_ip:
            return await call_next(request)

        if self.blacklist and client_ip in self.blacklist:
            return JSONResponse(status_code=403, content={"detail": "Access denied"})

        if self.whitelist and client_ip not in self.whitelist:
            return JSONResponse(status_code=403, content={"detail": "IP not in whitelist"})

        return await call_next(request)
```

### 纯 ASGI 原生中间件 vs BaseHTTPMiddleware

`BaseHTTPMiddleware` 简化了使用，但在某些场景下需要直接用 ASGI 原生接口：

```python
# BaseHTTPMiddleware 风格（简单但有限制）
class SimpleMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        # 可以访问 request/response 高级对象
        response = await call_next(request)
        response.headers["X-Custom"] = "value"
        return response

# 纯 ASGI 中间件风格（更底层，更灵活）
class RawASGIMiddleware:
    def __init__(self, app):
        self.app = app

    async def __call__(self, scope, receive, send):
        if scope["type"] != "http":
            await self.app(scope, receive, send)
            return

        # 请求前处理
        start = time.perf_counter()

        async def custom_send(message):
            # 响应后处理
            if message["type"] == "http.response.start":
                headers = dict(message.get("headers", []))
                headers[b"x-process-time"] = f"{time.perf_counter() - start:.4f}".encode()
                message["headers"] = list(headers.items())
            await send(message)

        await self.app(scope, receive, custom_send)
```

| 对比维度 | BaseHTTPMiddleware | 纯 ASGI 中间件 |
|---------|-------------------|---------------|
| 学习曲线 | 低 | 中 |
| 请求体访问 | 自动缓存，可多次读取 | 需手动处理 receive |
| 流式响应 | 自动缓存整个响应体 | 逐 chunk 处理，更高效 |
| 背景任务 | 与后台任务兼容 | 需显式处理 |
| WebSocket | 不适用 | 可处理 |
| 适用场景 | 大多数 HTTP 中间件 | 流式/WebSocket/高性能场景 |

**何时用纯 ASGI：** 需要处理流式响应（SSE）、WebSocket、对响应体逐块操作时。其他场景用 `BaseHTTPMiddleware` 即可。

### 中间件模式总结

| 模式 | 实现 | 适用场景 |
|------|------|---------|
| 洋葱模式 | `await call_next()` 前后操作 | 日志、计时、安全 Headers |
| 拦截模式 | 条件 return 跳过 call_next | CORS 预检、IP 黑名单、限流 |
| 增强模式 | 修改 request/receive 后 call_next | 注入 request_id、request.state |
| 包装模式 | 修改 response 后返回 | 添加响应头、压缩、加密 |
| 流式模式 | 通过 custom_send 逐块处理 | SSE、大文件下载、实时数据 |

```python
# 模式速查
@app.middleware("http")

    # === 1. 请求前（洋葱模式）===
    request.state.start_time = time.perf_counter()
    request.state.request_id = request.headers.get("X-Request-ID", str(uuid.uuid4()))

    # === 2. 拦截（条件返回）===
    if request.url.path == "/health":
        return JSONResponse({"status": "ok"})

    # === 3. 增强 request ===
    # 如需，可缓存或修改 request

    # === 4. 调用下一层 ===
    response = await call_next(request)

    # === 5. 包装响应 ===
    response.headers["X-Request-ID"] = request.state.request_id
    elapsed = time.perf_counter() - request.state.start_time
    response.headers["X-Response-Time"] = f"{elapsed:.3f}s"

    return response
```
