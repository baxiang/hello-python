# 03-依赖注入

> Python 3.11+

本章讲解 FastAPI 强大的依赖注入系统。

---

## 概念铺垫

FastAPI 的依赖注入系统本质上是一个 **有向无环图（DAG）解析器**。当路由函数声明依赖时，FastAPI 在启动时构建依赖图，运行时按拓扑序执行，并支持缓存和生命周期管理。

```
路由函数声明 Depends(get_current_user)
        │
        ▼ 依赖图解析
   get_db (叶子节点，无依赖)
        │
        ▼
   get_current_user (依赖 get_db)
        │
        ▼
   路由函数 (依赖 get_current_user)
```

**核心机制：**
- **图解析**：从 endpoint 开始递归解析所有依赖，检测循环依赖
- **拓扑排序**：按依赖关系确定执行顺序，无依赖的先执行
- **缓存（默认）**：同一请求内相同依赖函数只执行一次（可通过 `use_cache=False` 关闭）
- **yield 生命周期**：`try/finally` 模式确保资源在请求结束后被清理

依赖注入解耦了请求处理逻辑与资源管理（数据库连接、认证、配置），使代码更可测试、可复用。

## 第一部分：依赖注入基础

### 1.1 实际场景

多个路由需要访问数据库，不想在每个路由中重复创建数据库连接。

**问题：如何共享通用逻辑和资源？**

### 1.2 什么是依赖注入？

依赖注入是一种设计模式，允许将依赖项从外部注入到函数或类中。

```python
from fastapi import FastAPI, Depends

app: FastAPI = FastAPI()


# 定义依赖
def get_database() -> dict[str, str]:
    return {"connection": "database"}


# 使用依赖
@app.get("/items")
def get_items(db: dict[str, str] = Depends(get_database)) -> dict[str, dict]:
    return {"db": db}
```

### 3.3 带方法的类

```python
class Database:
    def __init__(self) -> None:
        self.connection: str = "connected"

    def query(self, sql: str) -> list[dict[str, str]]:
        return [{"id": 1, "name": "Item 1"}]

    def close(self) -> None:
        self.connection = "disconnected"


def get_database():
    db: Database = Database()
    try:
        yield db
    finally:
        db.close()


@app.get("/items")
def get_items(db: Database = Depends(get_database)) -> list[dict[str, str]]:
    return db.query("SELECT * FROM items")
```

## 第六部分：完整示例

```python
from fastapi import FastAPI, Depends, Header
from typing import Any

app: FastAPI = FastAPI()


# ==================== 依赖定义 ====================
class Pagination:
    def __init__(self, skip: int = 0, limit: int = 10):
        self.skip: int = skip
        self.limit: int = limit


def get_pagination(skip: int = 0, limit: int = 10) -> Pagination:
    return Pagination(skip=skip, limit=limit)


def verify_token(authorization: str | None = Header(default=None)) -> dict[str, str | int] | None:
    if not authorization:
        return None
    if not authorization.startswith("Bearer "):
        return None
    token: str = authorization.replace("Bearer ", "")
    return {"token": token, "user_id": 1}


def get_current_user(token_data: dict[str, str | int] | None = Depends(verify_token)) -> dict[str, str | int]:
    if not token_data:
        from fastapi import HTTPException
        raise HTTPException(status_code=401, detail="Not authenticated")
    return {"id": token_data["user_id"], "username": "john"}


# ==================== 路由 ====================
@app.get("/public/items")
def get_public_items(pagination: Pagination = Depends(get_pagination)) -> list[dict[str, str]]:
    items: list[dict[str, str]] = [{"id": i, "name": f"Item {i}"} for i in range(1, 101)]
    return items[pagination.skip:pagination.skip + pagination.limit]


@app.get("/private/items")
def get_private_items(
    pagination: Pagination = Depends(get_pagination),
    current_user: dict[str, str | int] = Depends(get_current_user)
) -> dict[str, str | list]:
    items: list[dict[str, str]] = [{"id": i, "name": f"Private Item {i}"} for i in range(1, 51)]
    return {
        "user": current_user["username"],
        "items": items[pagination.skip:pagination.skip + pagination.limit]
    }


@app.get("/profile")
def get_profile(current_user: dict[str, str | int] = Depends(get_current_user)) -> dict[str, str | int]:
    return current_user
```

### L2 实践层：用好

## 最佳实践

### 1. yield 依赖管理资源

对于需要清理的资源（数据库会话、文件句柄、网络连接），务必使用 `yield` 模式：

```python
# ✅ 自动清理
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()  # 异常时也会执行

# ❌ 容易泄漏
def get_db():
    return SessionLocal()  # 连接永不关闭
```

### 2. use_cache 使用策略

```
同一请求内，该依赖需要多次执行吗？
    ├── 否 ──> use_cache=True (默认)
    │         适用：数据库连接、用户认证、配置读取
    │         效果：同一请求内只执行一次
    │
    └── 是 ──> use_cache=False
              适用：需要最新状态的即时查询、计数器
              效果：每次出现都重新执行
```

### 3. 依赖链设计原则

- **深度不超过 3 层**：过深的依赖链增加调试和测试难度
- **每个依赖做一件事**：`get_db` 只负责数据库连接，`get_current_user` 只负责认证
- **避免在依赖中做业务逻辑**：依赖应用于资源准备和验证，而非业务流程

### 4. 可调用类作为权限依赖

```python
class RoleChecker:
    def __init__(self, allowed_roles: list[str]):
        self.allowed_roles = allowed_roles

    def __call__(self, current_user=Depends(get_current_user)):
        if current_user["role"] not in self.allowed_roles:
            raise HTTPException(403, "Insufficient permissions")
        return current_user

# 使用：可传入不同角色参数
@app.get("/admin")
def admin_only(user=Depends(RoleChecker(["admin"]))):
    ...
```

## 反模式

| ❌ 反模式 | ✅ 改进 |
|-----------|---------|
| 在依赖中 `raise HTTPException` 但没有 try/finally 保护资源 | yield 依赖保证 finally 块始终执行 |
| 所有依赖串成一条长链 `A→B→C→D→E` | 扁平化，同级依赖并行声明 |
| 同步依赖内执行异步 I/O | 互斥使用：同步依赖做计算，异步依赖做 I/O |
| `use_cache=True` 时依赖内部有可变状态 | 需要最新结果的依赖设置 `use_cache=False` |
| 滥用全局变量在依赖间传递数据 | 用依赖链自然传递，或使用 `Request.state` |
| 在 `@app.on_event("startup")` 中初始化依赖 | 使用 yield 依赖的 startup 部分或 lifespan |
| 忘记在 yield 的 finally 中关闭连接 | 始终 `try: yield resource / finally: resource.close()` |

## 何时选用什么

| 需求 | 选用方案 |
|------|---------|
| 简单参数共享 | 函数依赖 `Depends(get_pagination)` |
| 带内部状态的资源管理 | 类依赖 + yield `Depends(get_db)` |
| 基于角色的权限 | 可调用类 `Depends(RoleChecker(["admin"]))` |
| 认证后的用户信息 | 依赖链：`get_token → get_current_user` |
| 可选认证（公开+保护） | 依赖返回 `None`，路由判断 |
| 缓存依赖结果 | `use_cache=True`（默认） |
| 每次调用都执行 | `use_cache=False` |

### L3 专家层：深入

## 第七部分：L3 专家层

### 7.1 FastAPI 依赖注入的图解析（解决依赖链）

FastAPI 的依赖注入系统本质上是一个有向无环图（DAG）解析器。当路由函数声明了依赖，FastAPI 会构建依赖图并按拓扑序执行。

**图解析流程：**

```
路由函数: get_user(user=Depends(get_current_user))
                            │
                            ▼
                    ┌───────────────┐
                    │ get_current_  │
                    │     user      │
                    │   Depends:    │
                    │   get_db      │
                    └───────┬───────┘
                            │
                            ▼
                    ┌───────────────┐
                    │    get_db     │
                    │  (叶子节点)    │
                    └───────────────┘

解析后的执行顺序（拓扑排序）：

  Step 1: get_db()         ← 无依赖，最先执行
     │
     ▼
  Step 2: get_current_user(db=result_of_step1)
     │
     ▼
  Step 3: get_user(user=result_of_step2)
     │
     ▼
  返回响应
```

**核心实现（`fastapi.dependencies.utils.solve_dependencies`）：**

```python
# 伪代码展示图解析逻辑
async def solve_dependencies(
    *,
    request: Request,
    dependant: Dependant,  # 包含依赖函数的描述
    cache_dependencies: dict[int, Any],  # 依赖缓存
) -> dict[str, Any]:

    values: dict[str, Any] = {}
    sub_dependant: Dependant
    for sub_dependant in dependant.dependencies:
        # 检查缓存
        cache_key = id(sub_dependant.call)
        if cache_key in cache_dependencies:
            values[sub_dependant.name] = cache_dependencies[cache_key]
            continue

        # 递归解析子依赖
        solved = await solve_dependencies(
            request=request,
            dependant=sub_dependant,
            cache_dependencies=cache_dependencies,
        )
        # 调用依赖函数
        result = await run_in_threadpool(sub_dependant.call, **solved)
        values[sub_dependant.name] = result

    return values
```

**依赖图的特点：**
- **DAG 结构**：不允许循环依赖，FastAPI 在启动时检测并报错
- **拓扑排序**：按依赖关系确定执行顺序，无依赖的先执行
- **重复依赖合并**：同一个依赖函数在图中出现多次时只执行一次（除非 `use_cache=False`）

### 7.2 yield 依赖的生命周期管理

使用 `yield` 的依赖（如数据库会话）由 FastAPI 的生命周期管理机制处理。

**生命周期流程：**

```
请求开始
    │
    ▼
┌──────────────────────────────────────┐
│  1. 执行 yield 之前的代码（建立资源）  │
│     db = SessionLocal()              │
└──────────────┬───────────────────────┘
               │
               ▼
┌──────────────────────────────────────┐
│  2. yield 资源给路由函数               │
│     yield db                         │
│     路由函数执行...                    │
└──────────────┬───────────────────────┘
               │
               ▼
┌──────────────────────────────────────┐
│  3. 路由函数完成后                     │
│     a) 正常 → 执行 yield 之后的代码    │
│        try: yield db                 │
│        finally: db.close()  ← 执行   │
│     b) 异常 → 先传播异常再执行清理    │
│        finally 块仍会执行             │
└──────────────────────────────────────┘
               │
               ▼
        响应返回给客户端
```

**底层实现：**
- FastAPI 使用 `contextlib.contextmanager` 或 `contextlib.asynccontextmanager` 包装 yield 依赖
- 依赖被包装为 `Dependant` 对象，其中 `solve` 方法处理整个生命周期
- 异常传播：如果路由抛出异常，FastAPI 会在 `finally` 块中确保资源被清理，然后让异常继续传播

```python
# 内部处理逻辑（简化）
async def solve_yield_dependant(call: Callable) -> AsyncGenerator:
    cm = contextlib.asynccontextmanager(call)()  # 创建异步上下文管理器
    try:
        value = await cm.__aenter__()  # 执行 yield 前代码
        yield value                     # yield 给路由
    except Exception as e:
        await cm.__aexit__(type(e), e, e.__traceback__)  # 传递异常信息
        raise
    else:
        await cm.__aexit__(None, None, None)  # 正常退出
```

### 7.3 依赖缓存机制

FastAPI 默认对依赖结果进行缓存，同一请求内的相同依赖只执行一次。

**缓存行为：**

```
请求: GET /users/1/items/2

依赖声明:
  /users/{user_id} → Depends(get_user)
  /items/{item_id} → Depends(get_item)
  路由函数         → Depends(get_current_user)
                       └─ Depends(get_user)  ← 相同依赖

执行:
  1. get_user(user_id=1)   ← 执行，结果缓存
  2. get_item(item_id=2)   ← 执行，结果缓存
  3. get_current_user()
     └─ get_user(user_id=1) ← 命中缓存，跳过执行

缓存键: id(dependant.call)  # 依赖函数的内存地址
```

**缓存控制：**
- `Depends(func, use_cache=True)`：默认值，启用缓存
- `Depends(func, use_cache=False)`：每次调用都执行，适用于需要获取最新状态的场景

**缓存的作用域：** 缓存仅在当前请求内有效，不同请求之间不共享缓存结果。

### 7.4 性能考量

| 维度 | 说明 | 建议 |
|------|------|------|
| 图解析 | 启动时构建依赖图，运行时复用 | 依赖深度对性能影响极小 |
| 依赖缓存 | 同一请求内默认缓存 | 减少重复的 DB 查询或 API 调用 |
| yield 依赖 | 上下文管理器有微小开销 | 资源管理类依赖应使用 yield |
| 同步依赖 | 放入线程池执行 | I/O 密集型用 `async def` 依赖 |
| 依赖链深度 | 拓扑排序时间复杂度 O(V+E) | 实际场景中几乎无影响 |

### 7.5 设计动机

| 设计选择 | 原因 |
|----------|------|
| 图解析而非简单栈 | 支持复杂的依赖关系，自动解决执行顺序 |
| 默认缓存 | 大多数场景下同一依赖在同一请求中只需执行一次 |
| yield 支持 | 资源管理的 Pythonic 方式（RAII 模式） |
| 类型注解驱动 | 利用类型系统进行依赖推断和文档生成 |

### Level 3：yield 资源管理 + 异常安全

```python
from contextlib import asynccontextmanager
from fastapi import FastAPI, Depends
from sqlalchemy.ext.asyncio import AsyncSession

app = FastAPI()

async def get_db():
    async with AsyncSession(engine) as session:
        try:
            yield session
            await session.commit()  # 正常时提交
        except Exception:
            await session.rollback()  # 异常时回滚
            raise
        finally:
            await session.close()  # 无论如何都关闭
```

### Level 4：生产级依赖系统（多子依赖 + 缓存控制 + 异常包装）

```python
from dataclasses import dataclass
from fastapi import FastAPI, Depends, HTTPException, Request

app = FastAPI()


@dataclass
class AppState:
    db_healthy: bool = True
    cache_healthy: bool = True
    request_count: int = 0


def get_app_state(request: Request) -> AppState:
    return request.app.state.state


def get_database(state: AppState = Depends(get_app_state)):
    if not state.db_healthy:
        raise HTTPException(503, "Database unavailable")
    return {"connection": "active"}


def get_cache(state: AppState = Depends(get_app_state)):
    if not state.cache_healthy:
        raise HTTPException(503, "Cache unavailable")
    return {"redis": "connected"}


def get_current_user(payload: dict = Depends(parse_token)):
    if not payload:
        raise HTTPException(401, "Not authenticated")
    return {"id": payload.get("sub"), "role": payload.get("role")}


def require_role(role: str):
    def checker(user=Depends(get_current_user)):
        if user.get("role") != role:
            raise HTTPException(403, f"Requires role: {role}")
        return user
    return checker


@app.get("/dashboard")
async def dashboard(
    db=Depends(get_database),
    cache=Depends(get_cache),
    user=Depends(require_role("admin")),
):
    return {"db": db, "cache": cache, "user": user}
```

## 常见坑点排查

### 坑点 1：循环依赖导致启动失败

**症状：** 应用启动时报 `Depends` 循环错误

```python
# ❌ 循环依赖：A 依赖 B，B 依赖 A
def get_a(b=Depends(get_b)):
    return {"a": b}

def get_b(a=Depends(get_a)):
    return {"b": a}
```

**错误输出：**
```
ValueError: Detected dependency cycle: get_a -> get_b -> get_a
```

**根因分析：** FastAPI 在启动时构建依赖图，检测到循环依赖立即报错。DAG 不允许环存在。

```python
# ✅ 解决方案1：提取共享依赖
def get_shared():
    return {"shared": True}

def get_a(shared=Depends(get_shared)):
    return {"a": shared}

def get_b(shared=Depends(get_shared)):
    return {"b": shared}
```

```python
# ✅ 解决方案2：使用 use_cache=False 打破缓存层的循环引用
# (注意：这仍然不能解决真正的逻辑循环)
```

### 坑点 2：yield 依赖中提前 return

**症状：** yield 依赖中的资源没有被清理

```python
# ❌ 错误：验证失败时提前 return，跳过 finally
def get_db(user_id: int):
    if user_id < 0:
        return None  # 资源未创建，但仍跳过了后面的代码
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()  # 如果上面 return，这里不会执行
```

**根因分析：** 生成器函数中 `return` 会抛出 `StopIteration`，FastAPI 将其视为正常结束，`finally` 块不执行。但如果 `return` 在 `try` 块之前，`db` 本身未创建，问题不大。真正的问题是逻辑混淆。

```python
# ✅ 正确：始终在 try/finally 中管理资源
def get_db(user_id: int):
    if user_id < 0:
        raise HTTPException(400, "Invalid user_id")
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

### 坑点 3：`use_cache=True` 副作用

**症状：** 同一请求中多个 endpoint 使用了同一个带状态的依赖，但看到的是旧状态

```python
# ❌ 依赖内部有可变状态
counter = 0

def get_counter():
    global counter
    counter += 1
    return counter

@app.get("/a")
def a(c=Depends(get_counter)):
    return {"counter": c}  # 期望每次不同

@app.get("/b")
def b(c=Depends(get_counter)):
    return {"counter": c}  # 可能和 /a 一样（use_cache=True）
```

```python
# ✅ 设置 use_cache=False
@app.get("/a")
def a(c=Depends(get_counter, use_cache=False)):
    return {"counter": c}
```

### 坑点 4：依赖中直接访问 Request body 导致流被消费

**症状：** 中间件或依赖读取了 `request.body()` 后，端点中无法再次读取

```python
# ❌ request.body() 只能读一次
async def parse_body(request: Request):
    body = await request.body()  # 消费了 body 流
    return json.loads(body)

@app.post("/data")
async def handle(data: dict = Depends(parse_body)):
    pass  # 正常，但如果有多个依赖读 body 就会失败
```

```python
# ✅ 使用 FastAPI 内置 Body() 参数，或手动缓存 body
from fastapi import Body

@app.post("/data")
async def handle(data: dict = Body(...)):  # FastAPI 处理 body 读取
    pass
```

### 坑点排查速查表

| 症状 | 可能原因 | 排查方法 |
|------|---------|---------|
| 启动失败：循环依赖 | A→B→A 的依赖图 | 检查 Depends 调用链，扁平化依赖 |
| 资源泄漏 | yield 依赖无 finally | 确认所有 yield 依赖有 try/finally |
| 依赖被执行多次 | use_cache=False | 确认是否需要每次重新执行 |
| 依赖返回值是 None | 异步依赖中 return 忘了 await | 检查 async def 依赖的返回值 |
| 422 验证错误 | 依赖参数验证失败 | 检查依赖函数的参数类型与路由参数是否一致 |
| 权限依赖不生效 | 依赖未 raise HTTPException | 确认异常类型和状态码正确 |

```python
from fastapi import FastAPI, Depends
from fastapi.routing import APIRoute

app = FastAPI()

def print_dep_tree(app: FastAPI):
    for route in app.routes:
        if not isinstance(route, APIRoute):
            continue
        print(f"\nEndpoint: {route.path} [{','.join(route.methods)}]")
        _print_deps(route.dependant, indent=0)

def _print_deps(dependant, indent: int):
    prefix = "  " * indent
    name = getattr(dependant.call, "__name__", str(dependant.call))
    print(f"{prefix}├─ {name}")
    cache_info = "cached" if dependant.use_cache else "no-cache"
    print(f"{prefix}│  ({cache_info})")
    for sub in dependant.dependencies:
        _print_deps(sub, indent + 1)

print_dep_tree(app)
```

### Request-Scoped Singleton（请求作用域单例）

默认的 `use_cache=True` 已经实现了请求作用域的缓存。但有时你需要更精细的控制：

```python
from typing import Any
from fastapi import Request

class RequestContext:
    """请求作用域的状态容器。同时只能使用 async def 依赖访问。"""

    def __init__(self):
        self._store: dict[str, Any] = {}

    def set(self, key: str, value: Any):
        self._store[key] = value

    def get(self, key: str, default=None):
        return self._store.get(key, default)

def get_request_context(request: Request) -> RequestContext:
    # 每个请求有一个独立的 context 实例
    ctx = RequestContext()
    return ctx

@app.get("/demo")
async def demo(ctx=Depends(get_request_context)):
    ctx.set("user_id", 42)
    return {"ctx_type": type(ctx).__name__}
```

### 安全依赖组合模式

```python
from fastapi import Depends, HTTPException, Security
from fastapi.security import OAuth2PasswordBearer, APIKeyHeader, APIKeyQuery

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")
api_key_header = APIKeyHeader(name="X-API-Key")
api_key_query = APIKeyQuery(name="api_key")

# 方案1：任一认证通过即可
def get_auth(
    token_result=Depends(get_token_user_none_on_fail),
    api_key_result=Depends(get_api_key_user_none_on_fail),
):
    if token_result or api_key_result:
        return token_result or api_key_result
    raise HTTPException(401, "Authentication required")

# 方案2：多层安全，组合使用
def get_secure_user(
    user=Depends(get_current_user),
    api_key=Security(api_key_header),

    # 既需要 JWT token，也需要 API Key
    validate_api_key(user["id"], api_key)
    return user

# 方案3：Security 与 Depends 的区别

# Security → 出现在 /docs 的 "Authorize" 按钮
```

### 性能基准：依赖深度对响应时间的影响

| 场景 | 每请求开销 (μs) | 说明 |
|------|----------------|------|
| 无依赖 | 0 | 基线 |
| 1 层依赖 | ~5 | 单次 Depends 调用 |
| 3 层依赖链 | ~15 | 三层嵌套 Depends |
| 5 层依赖链 | ~25 | 五层嵌套 Depends |
| 3 个同级依赖 | ~15 | 3 个无依赖关系的 Depends |
| yield 依赖 | ~10 | 上下文管理器创建/清理 |
| 带缓存的重复依赖 | ~2 | 缓存命中，几乎零开销 |

> 依赖解析相对于实际业务逻辑（数据库查询、网络调用）的开销完全可以忽略。

### 依赖解析可视化工具

```python
"""
生成依赖图的 PlantUML/Mermaid 文本，帮助理解复杂依赖关系
"""

def generate_dep_mermaid(app: FastAPI) -> str:
    lines = ["graph TD"]
    edges = set()

    for route in app.routes:
        if not isinstance(route, APIRoute):
            continue
        endpoint_name = f"{route.name}({route.path})"
        _collect_edges(route.dependant, endpoint_name, edges)

    for parent, child in sorted(edges):
        lines.append(f"    {parent} --> {child}")

    return "\n".join(lines)

def _collect_edges(dependant, parent_name, edges):
    for sub in dependant.dependencies:
        child_name = getattr(sub.call, "__name__", str(sub.call))
        edges.add((parent_name, child_name))
        _collect_edges(sub, child_name, edges)

# 输出 Mermaid 格式，可粘贴到 mermaid.live 查看
print(generate_dep_mermaid(app))
```

### 依赖实例化时机对比

| 时机 | 说明 | 示例 |
|------|------|------|
| 请求时（默认） | 每次请求创建新实例 | `Depends(get_db)` |
| 应用启动时 | 创建后复用所有请求 | `lifespan` 中初始化并存入 `app.state` |
| 首次请求时 | 懒加载，第一次请求创建后缓存 | 配合模块级 `lru_cache` |
| 每次出现时 | `use_cache=False` | 需要最新状态的依赖 |

```python
from functools import lru_cache
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    DATABASE_URL: str
    SECRET_KEY: str

@lru_cache()
def get_settings() -> Settings:
    return Settings()

# 全局复用同一个 Settings 实例（应用级单例）
async def get_config(settings: Settings = Depends(get_settings)):
    return settings
```
