# 04-数据库集成

> Python 3.11+

本章讲解 FastAPI 与 SQLAlchemy 数据库集成。

---

## 概念铺垫

SQLAlchemy 是 Python 最流行的 ORM，2.0 版本引入原生 async 支持，通过 `sqlalchemy.ext.asyncio` 模块与 FastAPI 的异步事件循环无缝集成。

```
FastAPI Endpoint (async def)
    │
    ▼ Depends(get_async_db)
AsyncSession
    │
    ▼
AsyncEngine
    │
    ├── asyncpg (PostgreSQL, 推荐生产环境)
    └── aiosqlite (SQLite, 开发/测试)
```

**核心概念：**
- **AsyncSession**：异步版本的 Session，所有数据库操作需 `await`
- **连接池**：通过 `pool_size` + `max_overflow` 管理并发连接，避免频繁建立/关闭连接
- **事务隔离**：`READ COMMITTED`（默认）平衡性能与一致性，高一致性需求用 `REPEATABLE READ`
- **expire_on_commit**：commit 后属性过期，async 场景建议设为 `False` 避免额外查询

与 FastAPI 的关系：
- 通过 yield 依赖注入管理 session 生命周期
- `ConfigDict(from_attributes=True)` 支持 ORM 模型直接转为 Pydantic 响应模型
- 异步 session 配合 `async def` 端点，充分利用事件循环

```python
def update_user(db: Session, user_id: int, user_update: dict) -> User | None:
    db_user: User | None = db.query(User).filter(User.id == user_id).first()
    if db_user:
        for key, value in user_update.items():
            setattr(db_user, key, value)
        db.commit()
        db.refresh(db_user)
    return db_user
```

## 第五部分：完整示例

```python
from fastapi import FastAPI, Depends
from sqlalchemy import create_engine, Column, Integer, String, Boolean, DateTime
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.orm import sessionmaker, Session
from pydantic import BaseModel
from datetime import datetime
from typing import Any

app: FastAPI = FastAPI()

# ==================== 数据库配置 ====================
DATABASE_URL: str = "sqlite:///./app.db"
engine = create_engine(DATABASE_URL)
SessionLocal: sessionmaker[Session] = sessionmaker(autocommit=False, autoflush=False, bind=engine)
Base = declarative_base()

# ==================== 模型 ====================
class User(Base):
    __tablename__ = "users"

    id: int = Column(Integer, primary_key=True, index=True)
    username: str = Column(String(50), unique=True, index=True)
    email: str = Column(String(120), unique=True, index=True)
    is_active: bool = Column(Boolean, default=True)
    created_at: datetime = Column(DateTime, default=datetime.utcnow)

Base.metadata.create_all(bind=engine)

# ==================== Pydantic 模型 ====================
class UserCreate(BaseModel):
    username: str
    email: str


class UserResponse(BaseModel):
    id: int
    username: str
    email: str
    is_active: bool
    created_at: datetime

    model_config = ConfigDict(from_attributes=True)

# ==================== 依赖 ====================
def get_db() -> Session:
    db: Session = SessionLocal()
    try:
        yield db
    finally:
        db.close()

# ==================== 路由 ====================
@app.post("/users", response_model=UserResponse, status_code=201)
def create_user(user: UserCreate, db: Session = Depends(get_db)) -> User:
    db_user: User = User(**user.model_dump())
    db.add(db_user)
    db.commit()
    db.refresh(db_user)
    return db_user


@app.get("/users", response_model=list[UserResponse])
def get_users(skip: int = 0, limit: int = 10, db: Session = Depends(get_db)) -> list[User]:
    users: list[User] = db.query(User).offset(skip).limit(limit).all()
    return users


@app.get("/users/{user_id}", response_model=UserResponse)
def get_user(user_id: int, db: Session = Depends(get_db)) -> User:
    user: User | None = db.query(User).filter(User.id == user_id).first()
    if not user:
        from fastapi import HTTPException
        raise HTTPException(status_code=404, detail="User not found")
    return user


@app.delete("/users/{user_id}", status_code=204)
def delete_user(user_id: int, db: Session = Depends(get_db)) -> None:
    user: User | None = db.query(User).filter(User.id == user_id).first()
    if user:
        db.delete(user)
        db.commit()
    return None
```

### L2 实践层：用好

## 最佳实践

### 1. Session 管理：一个请求一个 Session

```python
# ✅ 正确：yield 确保 finally 块始终执行
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

# ❌ 错误：连接永不释放
def get_db():
    return SessionLocal()
```

**关键规则**：
- Session 生命周期 = 请求生命周期
- `commit()` 在 endpoint 中显式调用（或在返回前）
- `rollback()` 由异常处理器自动触发（yield 的 finally 块）
- 不要在 Session 之外访问 ORM 对象的懒加载属性（会触发 `DetachedInstanceError`）

### 2. 异步 vs 同步选择

```
端点是否有 I/O 等待（数据库查询）？
    ├── 是 ──> 异步端点是否有高并发需求？
    │          ├── 是 ──> async def + AsyncSession + asyncpg
    │          │         生产环境 PostgreSQL 推荐方案
    │          │
    │          └── 否 ──> def + Session 也可接受
    │
    └── 否 ──> def（纯计算，放入线程池）
```

| 场景 | 方案 | 数据库 |
|------|------|--------|
| 高并发 API | `async def` + `AsyncSession` | PostgreSQL + asyncpg |
| 中等并发 | `def` + `Session`（线程池） | PostgreSQL / SQLite |
| 开发/测试 | `async def` + `AsyncSession` | SQLite + aiosqlite |
| 批量处理 | `async def` + Core（raw SQL） | PostgreSQL + asyncpg |

### 3. 连接池配置

```python
engine = create_async_engine(
    DATABASE_URL,
    pool_size=5,          # 常驻连接数
    max_overflow=10,      # 超额连接数（峰值 = 5+10 = 15）
    pool_timeout=30,      # 超时等待时间（秒）
    pool_recycle=3600,    # 连接最大存活时间（秒），防止数据库断开空闲连接
    pool_pre_ping=True,   # 使用前测试连接是否有效
    echo=False,           # 生产环境务必关闭 SQL 日志
)
```

### 4. 避免 N+1 查询

```python
# ❌ N+1 查询：每条 Post 查询一次 Author
posts = db.query(Post).all()
for post in posts:
    print(post.author.name)  # 每次触发一次查询

# ✅ 预加载关联数据
from sqlalchemy.orm import joinedload
posts = db.query(Post).options(joinedload(Post.author)).all()
for post in posts:
    print(post.author.name)  # 已预加载，无额外查询
```

## 反模式

| ❌ 反模式 | ✅ 改进 |
|-----------|---------|
| 在请求之间复用 Session | 每个请求创建独立的 Session |
| 异步端点上用同步 Session | `async def` 配合 `AsyncSession` |
| 查询时不设置 `limit()` | 始终添加分页限制 |
| 循环中逐条 `flush()` | 批量操作后统一 `commit()` |
| ORM 查询返回全部字段 (`SELECT *`) | 用 `select(Col1, Col2)` 或 `with_only_columns()` 限制列 |
| 忘记 `expire_on_commit=False` | async session 必须设置，避免 commit 后额外 lazy load |
| `pool_pre_ping=False` 且数据库有超时断开 | 开启 `pool_pre_ping=True` 防止使用已断开连接 |
| 表创建用 `Base.metadata.create_all()` 在生产环境 | 使用 Alembic 版本迁移 |

## 何时选用什么

| 需求 | 选用方案 |
|------|---------|
| 常规 CRUD | SQLAlchemy ORM + Session |
| 复杂聚合查询 | SQLAlchemy Core（text/select） |
| 高并发 + PostgreSQL | async def + AsyncSession + asyncpg |
| 本地开发/单测 | SQLite + aiosqlite |
| 数据迁移 | Alembic |
| 连接健康检查 | `pool_pre_ping=True` |
| 大表 COUNT | 缓存或估算，避免每次请求 COUNT(*) |

## 第六部分：L3 专家层

### 6.1 SQLAlchemy 2.0 的 async 引擎（asyncpg/aiosqlite）

SQLAlchemy 2.0 引入了原生 async 支持，通过 `sqlalchemy.ext.asyncio` 模块提供异步引擎和会话。

**异步引擎架构：**

```
AsyncSession
    │
    ▼
┌──────────────────────────────────┐
│     AsyncEngine (SQLAlchemy)      │
│  ┌────────────────────────────┐  │
│  │  AsyncAdaptedQueue          │  │
│  │  (async 连接池队列)          │  │
│  └────────────┬───────────────┘  │
│               │                   │
│               ▼                   │
│  ┌────────────────────────────┐  │
│  │  AsyncAdaptedConnection     │  │
│  │  (包装底层 async 驱动)       │  │
│  │  ┌──────────────────────┐  │  │
│  │  │ asyncpg (PostgreSQL) │  │  │
│  │  │ aiosqlite (SQLite)   │  │  │
│  │  │ aiomysql (MySQL)     │  │  │
│  │  └──────────────────────┘  │  │
│  └────────────────────────────┘  │
└──────────────────────────────────┘
```

**驱动对比：**

```python
# PostgreSQL + asyncpg（生产推荐）
from sqlalchemy.ext.asyncio import create_async_engine

engine: AsyncEngine = create_async_engine(
    "postgresql+asyncpg://user:pass@localhost/dbname",
    echo=True,
)

# SQLite + aiosqlite（开发/测试）
engine: AsyncEngine = create_async_engine(
    "sqlite+aiosqlite:///./test.db",
    echo=True,
)
```

**核心区别：**
- `asyncpg`：基于 PostgreSQL 协议直接实现，性能最高，不支持 SQLite
- `aiosqlite`：在线程池中运行同步 `sqlite3`，通过 `anyio.to_thread` 桥接
- `echo=True`：输出 SQL 日志，生产环境应关闭

### 6.2 连接池的 async 适配

SQLAlchemy 的连接池在 async 环境下通过 `AsyncAdaptedQueue` 实现。

**连接池工作流程：**

```
                   AsyncEngine
                       │
                       ▼
              ┌─────────────────┐
              │   Connection     │
              │     Pool         │
              │                  │
              │  pool_size=5     │  ← 常驻连接数
              │  max_overflow=10 │  ← 最大溢出连接
              │  pool_timeout=30 │  ← 获取超时(秒)
              │  pool_recycle=   │  ← 连接回收时间
              │    3600          │
              └────────┬────────┘
                       │
              ┌────────┴────────┐
              │  AsyncAdapted   │
              │    Queue        │
              │  (FIFO async)   │
              └────────┬────────┘
                       │
            ┌──────────┼──────────┐
            ▼          ▼          ▼
         conn1      conn2      conn3
         (asyncpg  (asyncpg  (asyncpg
          connect)  connect)  connect)
```

**关键参数说明：**

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `pool_size` | 5 | 池中保持的常驻连接数 |
| `max_overflow` | 10 | 超出 pool_size 后可临时创建的连接数 |
| `pool_timeout` | 30 | 获取连接的最大等待时间（秒） |
| `pool_recycle` | -1（不回收） | 连接回收间隔（秒），防止数据库断开空闲连接 |
| `pool_pre_ping` | False | 每次获取连接前测试连通性 |

### 6.3 事务隔离级别

SQLAlchemy 支持多种事务隔离级别，直接影响并发读写的一致性。

**隔离级别对比：**

```
隔离级别 (由弱到强):

  READ UNCOMMITTED    ← 可能读到其他事务未提交的数据（脏读）
       │
       ▼
  READ COMMITTED      ← 只读到已提交的数据，但同一事务内两次读取可能不同（不可重复读）
       │
       ▼
  REPEATABLE READ     ← 同一事务内多次读取结果一致，但可能出现幻读
       │
       ▼
  SERIALIZABLE        ← 完全隔离，事务串行执行，性能最低
```

**SQLAlchemy 中设置：**

```python
from sqlalchemy import create_engine

# 引擎级别设置
engine = create_engine(
    "postgresql+asyncpg://user:pass@localhost/db",
    isolation_level="REPEATABLE READ",  # PostgreSQL
)

# SQLite 仅支持两种模式
engine = create_engine(
    "sqlite+aiosqlite:///./test.db",
    connect_args={"check_same_thread": False},
)
# SQLite 通过 PRAGMA 设置: PRAGMA journal_mode=WAL;

# 会话级别设置（覆盖引擎级别）
async with async_session() as session:
    await session.connection(
        execution_options={"isolation_level": "SERIALIZABLE"}
    )
    # 在此连接上的操作使用 SERIALIZABLE 隔离级别
```

**各数据库支持的隔离级别：**

| 数据库 | READ UNCOMMITTED | READ COMMITTED | REPEATABLE READ | SERIALIZABLE |
|--------|------------------|----------------|-----------------|--------------|
| PostgreSQL | ❌ (映射为 READ COMMITTED) | ✅ | ✅ | ✅ |
| MySQL | ✅ | ✅ | ✅ (默认) | ✅ |
| SQLite | ❌ | ✅ (默认) | ❌ | ✅ |

### 6.4 性能考量

| 维度 | 说明 | 建议 |
|------|------|------|
| asyncpg | 直接协议实现，零 Python 对象转换 | 生产环境首选 PostgreSQL 驱动 |
| aiosqlite | 线程池桥接，有上下文切换开销 | 仅用于开发/测试 |
| 连接池大小 | 过大浪费资源，过小导致等待 | 根据并发量调整，通常 5-20 |
| pool_pre_ping | 每次获取连接前 ping | 数据库不稳定时开启 |
| `expire_on_commit` | 默认 True，commit 后属性过期 | async 场景设为 False 避免额外查询 |

### 6.5 设计动机

| 设计选择 | 原因 |
|----------|------|
| async 引擎 | FastAPI 是异步框架，同步 DB 调用会阻塞事件循环 |
| 连接池 | 数据库连接建立开销大，复用可显著提升性能 |
| 事务隔离 | 不同业务场景对一致性和性能的需求不同 |
| ORM + Core 并存 | ORM 适合业务逻辑，Core 适合复杂查询和批量操作 |

## 渐进式代码示例

### Level 1：同步 SQLAlchemy 最简 CRUD

```python
from fastapi import FastAPI
from sqlalchemy import create_engine, Column, Integer, String
from sqlalchemy.orm import Session, sessionmaker, declarative_base

app = FastAPI()
engine = create_engine("sqlite:///./app.db")
SessionLocal = sessionmaker(bind=engine)
Base = declarative_base()

class User(Base):
    __tablename__ = "users"
    id = Column(Integer, primary_key=True)
    name = Column(String(50))

Base.metadata.create_all(bind=engine)

@app.get("/users")
def list_users():
    with SessionLocal() as db:
        return [{"id": u.id, "name": u.name} for u in db.query(User).all()]

@app.post("/users")
def create_user(name: str):
    with SessionLocal() as db:
        u = User(name=name)
        db.add(u)
        db.commit()
        db.refresh(u)
        return {"id": u.id, "name": u.name}
```

### Level 2：异步 SQLAlchemy + 依赖注入

```python
from sqlalchemy.ext.asyncio import create_async_engine, AsyncSession, async_sessionmaker

DATABASE_URL = "sqlite+aiosqlite:///./async.db"
async_engine = create_async_engine(DATABASE_URL)
AsyncSessionLocal = async_sessionmaker(async_engine, expire_on_commit=False)

async def get_db():
    async with AsyncSessionLocal() as session:
        yield session

@app.get("/users")
async def list_users(db: AsyncSession = Depends(get_db)):
    result = await db.execute(select(User))
    return [{"id": u.id, "name": u.name} for u in result.scalars().all()]
```

### Level 3：Repository 模式 + 数据库迁移

```python
from typing import TypeVar, Generic

ModelType = TypeVar("ModelType")
CreateType = TypeVar("CreateType")

class BaseRepository(Generic[ModelType, CreateType]):
    def __init__(self, model: type[ModelType], db: AsyncSession):
        self.model = model
        self.db = db

    async def create(self, obj_in: CreateType) -> ModelType:
        obj = self.model(**obj_in.model_dump())
        self.db.add(obj)
        await self.db.flush()
        return obj

    async def get(self, id: int) -> ModelType | None:
        return await self.db.get(self.model, id)

    async def list(self, skip=0, limit=20) -> list[ModelType]:
        result = await self.db.execute(
            select(self.model).offset(skip).limit(limit)
        )
        return list(result.scalars().all())

class UserRepository(BaseRepository[User, UserCreate]):
    async def get_by_email(self, email: str) -> User | None:
        result = await self.db.execute(
            select(User).where(User.email == email)
        )
```

## 常见坑点排查

### 坑点 1：AsyncSession 中访问 lazy-loaded 关系

**症状：** `sqlalchemy.exc.MissingGreenlet` 或 `DetachedInstanceError`

```python
# ❌ 在 async 环境中访问懒加载关系
async def get_author_with_books(author_id: int, db: AsyncSession):
    author = await db.get(Author, author_id)
    return author.books  # MissingGreenlet! 在 greenlet 外部访问
```

**根因分析：** SQLAlchemy 的 async 模式使用 greenlet（隐式异步转同步）。当通过 `await db.get()` 获取对象后，`author.books` 的访问需要回到数据库查询，但这需要在 greenlet 上下文中执行。

```python
# ✅ 预加载关联数据
from sqlalchemy import select
from sqlalchemy.orm import selectinload

async def get_author_with_books(author_id: int, db: AsyncSession):
    result = await db.execute(
        select(Author)
        .options(selectinload(Author.books))
        .where(Author.id == author_id)
    )
    return result.scalar_one_or_none()
```

### 坑点 2：连接池耗尽

**症状：** 接口响应变慢，最终返回 `QueuePool limit reached` 错误

```python
# ❌ 未设置 max_overflow，高并发下连接池耗尽
engine = create_async_engine(
    DATABASE_URL,
    pool_size=5,       # 仅 5 个常驻连接
    max_overflow=0,    # 无溢出连接
    pool_timeout=30,
)
```

**根因分析：** 当并发请求数 > pool_size 时，新请求在等待队列中阻塞。如果所有连接都在处理长时间查询，后续请求会超时。

```python
# ✅ 根据并发量调整
engine = create_async_engine(
    DATABASE_URL,
    pool_size=10,       # 根据预期并发调整
    max_overflow=20,    # 允许 20 个临时连接
    pool_timeout=10,    # 减少等待时间，快速失败
    pool_recycle=1800,  # 30 分钟后回收连接
    pool_pre_ping=True, # 使用前检查连接
)
```

### 坑点 3：`expire_on_commit=True` 导致额外查询

**症状：** commit 后访问 ORM 对象属性触发意外的数据库查询

```python
# ❌ expire_on_commit=True (默认)
async_session = sessionmaker(engine, class_=AsyncSession)  # expire_on_commit=True

async with async_session() as session:
    user = await session.get(User, 1)
    await session.commit()
    print(user.name)  # 触发额外查询! 因为 commit 后属性过期
```

```python
# ✅ expire_on_commit=False
async_session = sessionmaker(
    engine,
    class_=AsyncSession,
    expire_on_commit=False,  # commit 后属性不过期
)
```

### 坑点 4：在 endpoint 中使用多个 session

**症状：** 数据不一致、部分提交成功部分失败

```python
# ❌ 一个 endpoint 中使用多个 session
@app.post("/transfer")
async def transfer(
    from_db=Depends(get_db),
    to_db=Depends(get_db),  # 同一个依赖但不同 session
):
    # from_db 和 to_db 是独立的 session，无法协同提交/回滚
    pass
```

```python
# ✅ 一个请求只使用一个 session
@app.post("/transfer")
async def transfer(db: AsyncSession = Depends(get_db)):
    # 所有操作在同一个 session 中 = 同一个事务
    sender = await db.get(Account, from_id)
    receiver = await db.get(Account, to_id)
    sender.balance -= amount
    receiver.balance += amount
    await db.commit()
```

### 坑点排查速查表

| 症状 | 可能原因 | 排查方法 |
|------|---------|---------|
| MissingGreenlet | 在 greenlet 外部访问 lazy 关系 | 使用 selectinload/joinedload 预加载 |
| QueuePool limit reached | 连接池大小不足 | 增加 pool_size/max_overflow |
| commit 后额外查询 | expire_on_commit=True | 关闭 expire_on_commit 或转换为 dict |
| 事务未提交数据丢失 | 忘了 await session.commit() | 检查 CRUD 操作后是否有 commit |
| SQLite 多线程错误 | check_same_thread 未关闭 | SQLite 时设置 connect_args |
| 慢查询无 limit | 忘记分页限制 | 所有列表查询添加 offset/limit |

### Repository Pattern 完整实现

```python
from typing import Generic, TypeVar, Any
from sqlalchemy.ext.asyncio import AsyncSession
from sqlalchemy import select, func, delete, update
from pydantic import BaseModel

Model = TypeVar("Model")
CreateSchema = TypeVar("CreateSchema", bound=BaseModel)
UpdateSchema = TypeVar("UpdateSchema", bound=BaseModel)


class Repository(Generic[Model, CreateSchema, UpdateSchema]):
    def __init__(self, model: type[Model], db: AsyncSession):
        self.model = model
        self.db = db

    async def create(self, obj_in: CreateSchema) -> Model:
        db_obj = self.model(**obj_in.model_dump())
        self.db.add(db_obj)
        await self.db.flush()
        await self.db.refresh(db_obj)
        return db_obj

    async def get(self, id: Any) -> Model | None:
        return await self.db.get(self.model, id)

    async def get_or_404(self, id: Any) -> Model:
        obj = await self.db.get(self.model, id)
        if not obj:
            raise HTTPException(404, f"{self.model.__name__} not found")
        return obj

    async def list(
        self, *, skip: int = 0, limit: int = 20, **filters
    ) -> list[Model]:
        stmt = select(self.model)
        for key, value in filters.items():
            if value is not None:
                stmt = stmt.where(getattr(self.model, key) == value)
        stmt = stmt.offset(skip).limit(limit)
        result = await self.db.execute(stmt)
        return list(result.scalars().all())

    async def count(self, **filters) -> int:
        stmt = select(func.count()).select_from(self.model)
        for key, value in filters.items():
            if value is not None:
                stmt = stmt.where(getattr(self.model, key) == value)
        result = await self.db.execute(stmt)
        return result.scalar()

    async def delete(self, id: Any) -> None:
        obj = await self.get_or_404(id)
        await self.db.delete(obj)
        await self.db.flush()

    async def update(self, id: Any, obj_in: UpdateSchema) -> Model:
        obj = await self.get_or_404(id)
        update_data = obj_in.model_dump(exclude_unset=True)
        for field, value in update_data.items():
            setattr(obj, field, value)
        await self.db.flush()
        await self.db.refresh(obj)
        return obj
```

### 性能基准：aiosqlite vs asyncpg

```python
import asyncio
import time

async def benchmark(db_url: str, label: str, iterations=100):
    engine = create_async_engine(db_url)
    async with engine.connect() as conn:
        start = time.perf_counter()
        for i in range(iterations):
            await conn.execute(
                text("SELECT :x + :y"), {"x": i, "y": i * 2}
            )
        elapsed = time.perf_counter() - start
    await engine.dispose()
    qps = iterations / elapsed
    print(f"{label}: {qps:.0f} queries/sec ({elapsed:.3f}s)")
    return qps


async def main():
    aio_qps = await benchmark(
        "sqlite+aiosqlite:///bench.db", "aiosqlite"
    )
    pg_qps = await benchmark(
        "postgresql+asyncpg://postgres@localhost/bench", "asyncpg"
    )
    print(f"\nasyncpg 比 aiosqlite 快 {pg_qps / aio_qps:.1f}x")
```

| 驱动 | 简单查询 QPS | 说明 |
|------|------------|------|
| aiosqlite (本地) | ~3,500 | 线程池桥接，上下文切换开销 |
| asyncpg (本地) | ~15,000 | 纯异步协议实现 |
| asyncpg (远程) | ~8,000 | 网络延迟影响 |

> 本地延迟 ~0.1ms，远程延迟 ~2-5ms。asyncpg + 连接池将 QPS 维持在 ~8000 级别。
