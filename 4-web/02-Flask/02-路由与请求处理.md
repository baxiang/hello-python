# 02-路由与请求处理

> Python 3.11+

本章讲解 Flask 路由系统、动态 URL、请求对象和响应构建。

## 概念铺垫

路由（Route）将 URL 映射到视图函数，`@app.route()` 装饰器用于注册路由。Flask 使用 Werkzeug 的 `Map` 和 `Rule` 类进行 URL 匹配和变量类型转换。

### L1 理解层：会用

## 第一部分：@app.route 装饰器

### 1.1 实际场景

你正在开发一个博客网站，需要为首页、文章列表、文章详情等不同页面设置不同的 URL 路径。

**问题：如何将 URL 路径映射到对应的处理函数？**

### 1.2 概念说明

路由（Route）将 URL 映射到视图函数，`@app.route()` 装饰器用于注册路由。

```python
from flask import Flask

app: Flask = Flask(__name__)


@app.route("/")
def index() -> str:
    return "首页"


@app.route("/about")
def about() -> str:
    return "关于我们"


@app.route("/contact")
def contact() -> str:
    return "联系方式"
```

**访问 URL：**
- http://localhost:5000/ → 首页
- http://localhost:5000/about → 关于我们
- http://localhost:5000/contact → 联系方式

### 1.3 路由装饰器进阶：methods 参数

```python
# 同一路由，不同 HTTP 方法
@app.route("/user", methods=["GET"])
def get_user():
    return {"method": "GET"}

@app.route("/user", methods=["POST"])
def create_user():
    return {"method": "POST"}

@app.route("/user", methods=["PUT", "PATCH"])
def update_user():
    return {"method": request.method}

# 设置路由默认值
@app.route("/api", defaults={"version": "v1"})
@app.route("/api/<version>")
def api(version: str):
    return {"api_version": version}

# 严格斜杠处理
app.url_map.strict_slashes = False  # /users 和 /users/ 都可用
```

### 1.4 渐进式代码示例：路由设计

##### 最简示例

```python
@app.route("/")
def home():
    return "Hello"
```

##### 进阶示例

```python
from flask import Flask, request

app = Flask(__name__)

@app.route("/user/<int:user_id>", methods=["GET", "PUT"])
def user(user_id: int):
    if request.method == "GET":
        return {"id": user_id, "action": "read"}
    elif request.method == "PUT":
        return {"id": user_id, "action": "update"}, 200
    return {"error": "Method not allowed"}, 405
```

##### 综合示例

```python
from flask import Flask, request, jsonify, url_for

app = Flask(__name__)

# 资源化路由设计
@app.route("/api/v1/posts", methods=["GET", "POST"])
def posts():
    if request.method == "GET":
        # 列表查询：/api/v1/posts?page=1&per_page=20&tag=python
        page = request.args.get("page", 1, type=int)
        per_page = request.args.get("per_page", 20, type=int)
        tag = request.args.get("tag")
        return {"posts": [], "page": page, "per_page": per_page, "tag": tag}
    elif request.method == "POST":
        data = request.get_json()
        return {"created": data}, 201

@app.route("/api/v1/posts/<int:post_id>", methods=["GET", "PUT", "DELETE"])
def post_detail(post_id: int):
    if request.method == "GET":
        return {"id": post_id, "url": url_for("post_detail", post_id=post_id)}
    elif request.method == "PUT":
        return {"updated": post_id}
    elif request.method == "DELETE":
        return {"deleted": post_id}, 200
```

## 第二部分：动态路由规则

### 2.1 实际场景

博客文章有不同 ID，如 `/post/1`、`/post/2`，你不想为每个 ID 都写一个路由函数。

**问题：如何用一个路由处理不同的 URL 参数？**

### 2.2 URL 变量类型转换器

使用尖括号 `<variable_name>` 可以在 URL 中捕获动态值并传递给视图函数。

```python
from flask import Flask

app: Flask = Flask(__name__)


@app.route("/user/<username>")
def show_user(username: str) -> str:
    """字符串类型（默认）"""
    return f"用户：{username}"


@app.route("/post/<int:post_id>")
def show_post(post_id: int) -> str:
    """整数类型"""
    return f"文章 ID: {post_id}"


@app.route("/price/<float:price>")
def show_price(price: float) -> str:
    """浮点数类型"""
    return f"价格：{price}"


@app.route("/path/<path:subpath>")
def show_path(subpath: str) -> str:
    """路径类型（可包含斜杠）"""
    return f"子路径：{subpath}"
```

**示例：博客文章 URL**

```python
# /article/2027/03/09/my-first-post
@app.route("/article/<int:year>/<int:month>/<int:day>/<slug:title>")
def article(year: int, month: int, day: int, title: str) -> str:
    return f"{year}年{month}月{day}日 - {title}"
```

### 2.3 内置转换器详解

| 转换器 | 匹配规则 | 示例 URL | 捕获值 |
|--------|---------|---------|--------|
| `string` | 不含 `/` 的任意文本 | `/user/alice` | `alice` |
| `int` | 正整数或负整数 | `/post/42` | `42` |
| `float` | 正浮点数或负浮点数 | `/price/19.99` | `19.99` |
| `path` | 含 `/` 的路径 | `/files/images/logo.png` | `images/logo.png` |
| `uuid` | UUID 格式字符串 | `/item/550e8400-e29b-...` | `UUID("550e8400-...")` |
| `any` | 枚举值之一 | `/category/python/` | `python` |

### 2.4 自定义转换器：正则表达式匹配

```python
from werkzeug.routing import BaseConverter, ValidationError

class RegexConverter(BaseConverter):
    """基于正则表达式的通用转换器"""
    def __init__(self, url_map, regex):
        super().__init__(url_map)
        self.regex = regex

class PhoneConverter(BaseConverter):
    """手机号转换器：匹配 11 位数字"""
    regex = r"1[3-9]\d{9}"

    def to_python(self, value: str) -> str:
        return value

    def to_url(self, value: str) -> str:
        return str(value)

class SlugConverter(BaseConverter):
    """SEO 友好的 URL Slug"""
    regex = r"[a-z0-9]+(?:-[a-z0-9]+)*"

class VersionConverter(BaseConverter):
    """语义化版本号：v1.2.3"""
    regex = r"v\d+\.\d+\.\d+"

app.url_map.converters["regex"] = RegexConverter
app.url_map.converters["phone"] = PhoneConverter
app.url_map.converters["slug"] = SlugConverter
app.url_map.converters["version"] = VersionConverter

@app.route("/user/phone/<phone:number>")
def user_by_phone(number: str):
    return f"手机号用户: {number}"

@app.route("/app/<version:ver>")
def app_version(ver: str):
    return f"应用版本: {ver}"
```

## 第三部分：URL 构建：url_for()

### 3.1 实际场景

你在代码中写了 `/user/profile` 这个 URL，后来路由规则改为 `/account/profile`，所有引用都要修改。

**问题：如何避免硬编码 URL，让代码易于重构？**

### 3.2 基本用法

`url_for()` 函数根据视图函数名生成 URL，避免硬编码 URL。

```python
from flask import Flask, url_for

app: Flask = Flask(__name__)


@app.route("/")
def index() -> str:
    return "首页"


@app.route("/user/<username>")
def user_profile(username: str) -> str:
    return f"{username}的主页"


# 生成 URL
print(url_for("index"))           # 输出：/
print(url_for("user_profile", username="张三"))  # 输出：/user/张三
```

**url_for() 的优势：**

```
┌─────────────────────────────────────────────────────────────┐
│              使用 url_for() 的优势                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   1. 易于重构                                               │
│      修改路由规则后，不需要修改所有引用该 URL 的地方         │
│                                                             │
│   2. 自动处理特殊字符                                        │
│      url_for('/user/张三') → /user/%E5%BC%A0%E4%B8%89       │
│                                                             │
│   3. 支持测试环境                                           │
│      测试时可以重定向到测试服务器                           │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.3 url_for 深度用法

```python
from flask import Flask, url_for

app = Flask(__name__)

# 静态文件 URL
# url_for('static', filename='css/style.css')
# → /static/css/style.css

# 蓝图内 URL（蓝图名称.视图函数名）
# url_for('admin.index')
# url_for('api.get_user', user_id=1)

# 带查询参数的 URL（额外参数自动转为查询字符串）
# url_for('index', page=2, q='python')
# → /?page=2&q=python

# 外部 URL（含完整域名）
with app.test_request_context():
    print(url_for("index"))              # /
    print(url_for("index", _external=True))  # http://localhost:5000/
    print(url_for("index", _anchor="section1"))  # /#section1
    print(url_for("index", _scheme="https", _external=True))  # https://localhost:5000/
```

### 3.4 常见错误与排查：url_for

| 错误现象 | 原因分析 | 解决方案 | 预防措施 |
|----------|---------|---------|---------|
| `BuildError: Could not build url for endpoint 'xxx'` | 视图函数不存在或未注册，或蓝图端点需要带前缀 | 检查函数名拼写，蓝图端点用 `'蓝图名.函数名'` | 使用 `app.url_map` 列出所有端点 |
| 生成的 URL 缺少参数 | 路由定义了参数但 `url_for` 未传递 | 补充缺失的 keyword 参数 | 输出路由规则 `str(rule)` 检查参数 |
| 生成的 URL 中出现乱码 | 中文参数被自动 URL 编码 | 这是正常行为，浏览器会自动解码 | 使用 `unquote()` 解码后显示 |

## 第四部分：重定向与 abort

### 4.1 实际场景

用户登录成功后需要跳转到首页，未登录用户访问管理页面需要返回 403 错误。

**问题：如何实现页面跳转和错误响应？**

### 4.2 示例代码

`redirect()` 用于跳转到其他 URL，`abort()` 用于立即返回错误状态码。

```python
from flask import Flask, redirect, abort, url_for, request
from typing import Optional

app: Flask = Flask(__name__)


# 永久重定向
@app.route("/old-page")
def old_page() -> str:
    return redirect(url_for("new_page"), code=301)


# 临时重定向
@app.route("/new-page")
def new_page() -> str:
    return "这是新页面"


# 根据条件重定向
@app.route("/admin")
def admin() -> str:
    user: Optional[dict] = get_current_user()  # 假设有这个函数
    if not user:
        return redirect(url_for("login"))
    if not user.get("is_admin"):
        abort(403)  # 返回 403 Forbidden
    return "管理员页面"


# 自定义错误页面
@app.errorhandler(403)
def forbidden(error) -> tuple[str, int]:
    return "您没有权限访问此页面", 403


@app.errorhandler(404)
def not_found(error) -> tuple[str, int]:
    return "页面未找到", 404


def get_current_user() -> Optional[dict]:
    """模拟获取当前用户"""
    return None
```

### 4.3 重定向码详解

| 状态码 | 语义 | 浏览器行为 | 适用场景 |
|--------|------|-----------|---------|
| 301 | 永久重定向 | 浏览器缓存目标 URL，后续直接跳转 | 网站迁移、URL 规范化 |
| 302 | 临时重定向（默认） | 不缓存，每次重新请求 | 表单提交后跳转、登录跳转 |
| 303 | See Other | GET 到目标 URL（即使原请求是 POST） | POST 后跳转（PRG 模式） |
| 307 | 临时重定向（保留方法） | 保留原请求方法和请求体 | API 临时迁移 |
| 308 | 永久重定向（保留方法） | 与方法 301 类似但保留请求方法和请求体 | API 永久迁移 |

## 第五部分：request 对象

### 5.1 实际场景

你需要知道访问者使用什么浏览器、从哪个 IP 地址访问、请求了什么 URL。

**问题：如何获取 HTTP 请求的详细信息？**

### 5.2 request 对象常用属性

Flask 的 `request` 对象封装了 HTTP 请求的所有信息。

```python
from flask import Flask, request

app: Flask = Flask(__name__)


@app.route("/request-info")
def request_info() -> str:
    """展示 request 对象的常用属性"""

    # 请求方法
    method: str = request.method  # GET, POST, PUT, DELETE, etc.

    # URL 信息
    url: str = request.url                # 完整 URL
    path: str = request.path              # 路径部分

    # 请求头
    user_agent: str = str(request.user_agent)  # 浏览器信息

    # 客户端信息
    remote_addr: str = request.remote_addr  # IP 地址

    return f"""
    <h3>请求信息</h3>
    <p>方法：{method}</p>
    <p>URL: {url}</p>
    <p>路径：{path}</p>
    <p>用户代理：{user_agent}</p>
    <p>IP 地址：{remote_addr}</p>
    """
```

### 5.3 request 对象完整属性参考

```python
# 请求方法
request.method          # "GET", "POST", "PUT", "DELETE", ...
request.is_secure       # 是否 HTTPS
request.is_json         # 是否 application/json

# URL 信息
request.url             # 完整 URL
request.base_url        # 基础 URL（不含查询参数）
request.path            # 路径部分

request.host            # 主机名:端口
request.host_url        # http://host:port/
request.root_path       # 应用挂载的根路径（代理后）

# 查询参数
request.args            # ImmutableMultiDict，GET 参数
request.args.get("q")   # 获取单个参数
request.args.getlist("tags")  # 获取多值参数

# 表单数据
request.form            # ImmutableMultiDict，POST 表单

request.form.getlist("hobbies")

# JSON 数据
request.get_json()      # 解析 JSON，失败返回 None
request.json            # 同 get_json(force=True)，失败抛异常

```

## 第六部分：获取请求数据

### 6.1 实际场景

用户在搜索框输入关键词，或在登录表单提交用户名密码，你需要获取这些数据。

**问题：如何获取不同类型的请求数据？**

### 6.2 获取查询参数

```python
from flask import Flask, request

app: Flask = Flask(__name__)


@app.route("/search")
def search() -> str:
    # URL: /search?q=python&page=2
    keyword: str = request.args.get("q", "")      # 获取单个参数
    page: int = request.args.get("page", 1, type=int)   # 带默认值和类型转换

    return f"搜索：{keyword}, 页码：{page}"
```

### 6.3 获取表单数据

```python
@app.route("/login", methods=["POST"])
def login() -> str:
    # Content-Type: application/x-www-form-urlencoded
    username: str = request.form.get("username", "")
    password: str = request.form.get("password", "")

    return f"登录用户：{username}"
```

### 6.4 获取 JSON 数据

```python
from flask import Flask, request, abort, jsonify
from typing import Any

app: Flask = Flask(__name__)


@app.route("/api/users", methods=["POST"])
def create_user() -> dict[str, Any]:
    # Content-Type: application/json
    data: dict[str, Any] = request.get_json()

    # 如果 JSON 格式无效，返回 400
    if not data:
        abort(400, description="无效的 JSON 数据")

    # 获取单个字段
    username: str = data.get("username", "")
    email: str = data.get("email", "")

    return {"message": f"创建用户：{username}"}
```

### 6.5 获取原始请求体

```python
# 获取原始字节流（如 Webhook 签名验证）
raw_data: bytes = request.get_data()
print(f"原始数据长度: {len(raw_data)} 字节")

# 逐行读取输入流（大请求体）
for line in request.input_stream:
    process_line(line)
```

### 6.6 常见错误与排查：请求数据

| 错误现象 | 原因分析 | 解决方案 | 预防措施 |
|----------|---------|---------|---------|
| `request.get_json()` 返回 `None` | Content-Type 不是 `application/json` | ① 确认请求头 ② 用 `silent=True` 不抛异常 ③ 或 `force=True` 强制解析 | 提供 `@app.before_request` 统一检查 |
| `request.args.get("page")` 返回字符串 | URL 查询参数始终是字符串 | 使用 `type=int` 参数：`request.args.get("page", 1, type=int)` | 封装 `parse_args()` 工具函数 |
| 大 JSON 请求体解析慢 | `json.loads()` 全量解析大数据 | ① 用 `MAX_CONTENT_LENGTH` 限制 ② 流式解析 `ijson` | 限制请求体大小 |
| POST 表单数据为空 | enctype 错误（未设置 `multipart/form-data`） | 表单设置 `enctype="multipart/form-data"` | 检查实际 Content-Type 头 |

## 第七部分：请求钩子

### 7.1 实际场景

每个请求都需要检查用户是否登录，每个请求结束后都要记录日志。

**问题：如何在请求处理的特定阶段自动执行代码？**

### 7.2 四种请求钩子

```python
import time
from flask import Flask, request, g, Response
from typing import Optional

app: Flask = Flask(__name__)


@app.before_request
def before_request() -> None:
    """在每个请求处理之前执行"""
    # 可用于：用户认证、日志记录、数据库连接
    print(f"处理请求：{request.method} {request.path}")
    g.start_time: float = time.time()  # g 对象用于存储请求级别的数据


@app.after_request
def after_request(response: Response) -> Response:
    """在每个请求处理之后执行（无异常时）"""
    # 可用于：添加响应头、记录日志
    response.headers["X-Custom-Header"] = "MyApp"
    return response  # 必须返回 response


@app.teardown_request
def teardown_request(exception: Optional[Exception] = None) -> None:
    """在请求结束时执行（无论是否有异常）"""
    # 可用于：关闭数据库连接、清理资源
    if exception:
        print(f"请求处理异常：{exception}")


@app.errorhandler(404)
def handle_404(error) -> tuple[str, int]:
    """错误处理器"""
    return "页面未找到", 404
```

### 7.3 钩子执行顺序与生命周期

```
┌─────────────────────────────────────────────────────────────────┐
│                    请求处理生命周期                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   请求到达                                                       │
│       │                                                         │
│       ▼                                                         │
│   1. before_request (多个按注册顺序执行)                          │
│       │  → 认证检查、权限验证、日志记录、数据库连接               │
│       │  → 如果返回 Response，跳过视图函数直接返回                │
│       ▼                                                         │
│   2. before_first_request (仅首次请求，Flask 2.3+ 已废弃)         │
│       │                                                         │
│       ▼                                                         │
│   3. 视图函数处理                                                │
│       │  → 路由匹配 → 执行视图函数 → 返回 Response               │
│       │                                                         │
│       ▼                                                         │
│   4. after_request (多个按注册顺序执行)                           │
│       │  → 添加响应头、修改响应体、记录日志                       │
│       │  → 必须接收并返回 Response 对象                          │
│       │                                                         │
│       ▼                                                         │
│   5. teardown_request (无论成功或异常都执行)                      │
│       │  → 关闭数据库连接、释放资源                               │
│       │  → 接收可选的 Exception 参数                             │
│       │                                                         │
│       ▼                                                         │
│   响应返回客户端                                                  │
│                                                                 │
```

### 7.4 请求钩子实战：认证与计流

```python
import time
import functools
from flask import Flask, request, g, Response, jsonify, abort

app = Flask(__name__)

# 模拟用户存储
TOKENS = {"token-alice": {"user_id": 1, "name": "Alice", "role": "admin"}}

@app.before_request
def authenticate():
    """全局认证钩子"""
    # 跳过不需要认证的路由
    if request.endpoint in ("login", "register", "health", None):
        return None

    token = request.headers.get("Authorization", "").replace("Bearer ", "")
    user = TOKENS.get(token)

    if not user:
        # 如果是 API 请求返回 JSON，否则重定向
        if request.path.startswith("/api/"):
            return jsonify({"error": "Unauthorized"}), 401
        abort(401)

    g.current_user = user

@app.before_request
def rate_limit():
    """简易限流钩子"""
    client_ip = request.remote_addr

    # 获取当前 IP 的计数器
    counter_key = f"rate:{client_ip}"
    if not hasattr(g, "rate_counters"):
        g.rate_counters = {}
    g.rate_counters[counter_key] = g.rate_counters.get(counter_key, 0) + 1

    if g.rate_counters.get(counter_key, 0) > 100:
        return jsonify({"error": "Too Many Requests"}), 429

@app.after_request
def add_security_headers(response: Response):
    """添加安全响应头"""
    response.headers["X-Content-Type-Options"] = "nosniff"
    response.headers["X-Frame-Options"] = "DENY"
    response.headers["X-XSS-Protection"] = "1; mode=block"
    response.headers["Strict-Transport-Security"] = "max-age=31536000"
    return response

@app.teardown_request
def cleanup(exception=None):
    """清理请求级资源"""
    if hasattr(g, "db_connection"):
        g.db_connection.close()
    if exception:
        app.logger.error(f"请求异常: {exception}")

@app.route("/api/me")
def me():
    user = g.get("current_user", {})
    return {"user": user}

@app.route("/health")
def health():
    return {"status": "ok"}
```

### 8.4 流式响应与服务器推送事件（SSE）

```python
import time
import json
from flask import Response, stream_with_context

@app.route("/stream/numbers")
def stream_numbers():
    """流式响应：每秒推送一个数字"""
    def generate():
        for i in range(10):
            yield f"data: {i}\n\n"
            time.sleep(1)
    return Response(generate(), mimetype="text/plain")

@app.route("/stream/events")
def sse_events():
    """服务器推送事件（Server-Sent Events）"""
    @stream_with_context
    def event_stream():
        for i in range(5):
            event = json.dumps({"iteration": i, "message": f"Event {i}"})
            yield f"data: {event}\n\n"
            time.sleep(2)
        yield "data: {\"done\": true}\n\n"

    return Response(
        event_stream(),
        mimetype="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "X-Accel-Buffering": "no",  # Nginx 禁用缓冲
        },
    )

@app.route("/stream/download")
def stream_download():
    """流式下载大文件"""
    def large_file_generator():
        with open("/path/to/large/file.zip", "rb") as f:
            while chunk := f.read(8192):
                yield chunk

    return Response(
        stream_with_context(large_file_generator()),
        headers={
            "Content-Disposition": "attachment; filename=large.zip",
            "Content-Type": "application/octet-stream",
        },
    )
```

### 10.3 session 的签名机制

Flask 的 session 默认使用客户端 cookie 存储，通过 ItsDangerous 库进行签名防止篡改。

```
┌─────────────────────────────────────────────────────────────────┐
│                Session 签名与验证流程                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   存储流程（响应阶段）：                                          │
│                                                                 │
│   session_data = {"username": "alice", "role": "user"}          │
│         │                                                       │
│         ▼                                                       │
│   1. JSON 序列化 → {"username":"alice","role":"user"}           │
│         │                                                       │
│         ▼                                                       │
│   2. URL-safe Base64 编码 → eyJ1c2VybmFtZSI6ImFsaWNlIn0        │
│         │                                                       │
│         ▼                                                       │
│   3. HMAC-SHA256 签名                                           │
│       输入：payload + secret_key + timestamp                    │
│       输出：.tJ9xK3mP...（签名后缀）                            │
│         │                                                       │
│         ▼                                                       │
│   4. 设置 Cookie: session=eyJ1c2VybmFtZSI6ImFsaWNlIn0.tJ9xK3mP  │
│                                                                 │
│   验证流程（请求阶段）：                                          │
│                                                                 │
│   1. 读取 Cookie → 分割 payload 和 signature                    │
│   2. 用 secret_key 重新计算签名                                  │
│   3. 对比签名 → 一致则反序列化，不一致则抛出 BadSignature        │
│   4. 检查时间戳 → 过期则抛出 SignatureExpired                   │
│                                                                 │
│   ⚠️ 注意：session 数据是编码而非加密！                          │
│      用户可以读取内容，但无法篡改（除非知道 secret_key）         │
│      敏感信息（密码、token）不应存入 session                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 10.4 性能考量

| 操作 | 耗时 | 内存 | 说明 |
|------|------|------|------|
| 路由匹配（50 条规则） | ~0.03ms | — | 线性扫描，最坏 O(n) |
| 路由匹配（500 条规则） | ~0.3ms | — | 规则数线性增长 |
| 上下文创建 + 销毁 | ~0.15ms | ~2KB | RequestContext 全生命周期 |
| session 签名（cookie 写入） | ~0.05ms | — | HMAC-SHA256 计算 |
| session 验证（cookie 读取） | ~0.05ms | — | 签名校验 + 反序列化 |
| request.args 解析 | ~0.02ms | ~1KB | URL 查询字符串解析 |
| request.get_json() | ~0.1ms | ~5KB | JSON 反序列化 |

**扩展性提示：** 客户端 session 随数据量增长而增大 cookie 体积（4KB 浏览器限制）。用户数据超过 1KB 时应改用服务端 session（Flask-Session + Redis）。

### 10.5 设计动机

| 设计决策 | 动机 | 权衡 |
|----------|------|------|
| 使用 ContextVar 存储上下文 | Python 3.7+ 原生支持，替代 thread-local | 需手动管理异步任务中的上下文传播 |
| 路由规则按注册顺序匹配 | 简单直观，开发者可预测 | 规则数量多时性能线性下降 |
| session 存于客户端 cookie | 无状态，易于水平扩展 | 数据大小受限，无法主动失效 |
| request 作为全局代理对象 | API 简洁，`from flask import request` | 在请求外访问会抛出 RuntimeError |
| 转换器系统可扩展 | 支持自定义 URL 参数解析 | 需手动注册到 url_map.converters |
